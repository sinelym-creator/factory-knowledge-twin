# tests/data — synthetic seed 데이터 정합 표본 (T1-2 검증 자산)

생성기가 만든 **데이터가 스펙·평가셋 전제와 맞는지**를 DB에서 확인한다.
`tests/schema`가 「스키마가 막아야 할 것을 막는가」를 보는 것과 짝이다.

## 실행

```powershell
docker compose up -d
pwsh services/ai-api/db/migrate.ps1     # 001 + 002
pwsh data/seed.ps1                      # 생성 → 적재 → 검증
pwsh tests/data/run-seed-integrity.ps1  # ① DB 데이터 정합 표본 (DB 필요)
python tests/data/selfcheck_mutation.py # ② 자기 점검 감지력 시험 (DB 불필요)
```

좌석별 병렬 스택은 `docs/product/dev-environment.md` §4.2를 따른다(포트·`VOLUME_ROOT` 분리).

| 자산 | 무엇을 재는가 | DB |
|---|---|---|
| `seed-integrity.sql` + `run-seed-integrity.ps1` | 적재된 **데이터**가 스펙·평가셋 전제와 맞는가 | 필요 |
| `selfcheck_mutation.py` | 생성기 **자기 점검이 실패를 «낼 수 있는가»**(위반 8종 주입) | 불필요 |

## 판정 규칙

| exit | 뜻 |
|---:|---|
| 0 | 표본 20건 전건 PASS |
| 1 | FAIL 1건 이상 — 데이터가 전제와 어긋난다 |
| 2 | 실행 오류(스택 미기동·표본 파일 없음·psql 실패) |

- **읽기 전용**이다. 어떤 행도 쓰지 않으므로 타 좌석 스택에서 돌려도 안전하다.
- 각 항목은 `기대값 = 실측값`의 단일 비교다. 서식이 아니라 **숫자**로 판정한다.

## 무엇을 보는가 — 그리고 무엇을 «보지 않는가»

🔴 **생성기 자기 점검(`data/generators/generate.py` `self_check`)이 이미 보는 축은 넣지 않았다.**
규모·금지 ID·D-2·D-5·GS 바인딩 존재는 생성 단계에서 이미 막힌다 — 자기 실측의 복창은 검증이 아니다.
(그 자기 점검이 **실제로 실패를 낼 수 있는지**는 별도로 시험했다 — 8종 위반 주입 전건 감지.
 `evidence/t1-2-seed-verification.md` §3.)

여기 있는 것은 그 바깥의 세 축이다.

| 축 | 항목 | 왜 여기 있나 |
|---|---|---|
| **스키마가 비강제로 확정한 정합** | C-10·C-11 (G-4b: `component.id`·`sensor.id`의 설비 번호 ↔ 실제 소속) | T1-1에서 「CHECK로 불가 · **T1-2 seed 생성 시 검증**」으로 이관된 축이다. 스키마도 자기 점검도 보지 않으므로 **여기가 유일한 그물**이다 |
| **주장했으나 어느 점검에도 없던 것** | C-9(비용 표현 전 text 칼럼 훑기) · C-12·C-13(알람 ↔ 시계열 **양방향**) · C-14(진행 중 incident 진단 누설) · C-18(시간 인과) | 생성기 README가 「지켰다」고 적은 것들. 적힌 것과 있는 것은 다르다 |
| **ID를 읽어 의미를 얻는다는 전제** | C-16·C-17 (`MR/INC/WO/AL-{날짜}` ↔ 실제 시각) | 이 프로젝트는 ID에서 소속·시점을 읽는다(§3.1). 어긋난 행은 예외도 로그도 없이 **조용히** 틀린 답을 만든다 |

C-13은 특히 **역방향**이다. 생성기는 「알람 → 그 시각 계측값」을 맞췄지만, 「임계를 넘었는데 알람이 없다」는
반대 방향은 재지 않았다. 둘 다 성립해야 시계열과 알람이 정합하다.

## 자기 점검 감지력 시험 (`selfcheck_mutation.py`)

생성기 파일을 수정하지 않는다. `build_all` 결과를 **복제해 메모리에서만** 위반을 주입하고 `self_check`만 다시 부른다.
판정은 「감지했는가」가 아니라 **「표와 같은가」**다 — 알려진 구멍은 `False`로 고정돼 있어,
**새로 뚫린 구멍**과 **메워진 구멍**이 둘 다 exit 1로 드러난다.

| exit | 뜻 |
|---:|---|
| 0 | 대조군 통과 + 감지 결과가 표와 일치 |
| 1 | 대조군이 실패했거나, 감지 결과가 표와 다르다 |

**현재: 주입 8건 · 감지 7건 · 알려진 구멍 1건(F-2) · exit 0.**

## 🔴 알려진 FAIL — 1건 (2026-08-28 기준)

| check | 실측 | 상태 |
|---|---|---|
| **C-16** `MR-{YYYY}` ↔ `performed_at` 연도 불일치 | 40건 중 **13건** | **미수정** — `evidence/t1-2-seed-verification.md` **F-1** |

`MR-2025-0081~0084`는 실제 2024년, `MR-2025-0090~0098`은 실제 **2026-08-23** 수행이다.
같은 규칙을 쓰는 `INC`·`WO`·`AL`은 전건 정합(C-17 PASS)이라 **MR만 빠진 것**이다.

**그래서 이 표본은 지금 exit 1을 낸다.** 초록이 아닌 것이 정상이다 — 결함이 실재하기 때문이다.
F-1이 수정되면 별도 변경 없이 20/20 · exit 0으로 뒤집힌다. 뒤집히지 않으면 처방이 반영되지 않은 것이다.

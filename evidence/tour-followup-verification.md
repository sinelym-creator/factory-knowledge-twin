## 1. preflight 가 D-87 이전 전제를 들고 있었다 — 교체 (E1)

### 교체 «전» — 내 손으로 빨강을 재현했다

```
FKT_WEB_BASE=:8195 FKT_API_BASE=:8020  npx playwright test session-guard.spec.ts
rc 1 · preflight.ts:56 throw
```

`tests/web/playwright.config.ts` 의 `globalSetup` 이 이 파일이므로 **`tests/web/e2e/**` 전량이 한 본도 서지 못한다**. 원인은 무대가 아니다. 깊은 검사가 `GET /openapi.json` 의 `paths` 하한 10 을 요구하는데 **D-87 이 그 표면을 닫아** `:8020/openapi.json` 이 **404** 이고, 그래서 `pathCount = -1` 로 **항상** throw 한다.

### 교체 «후»

깊이를 포기하지 않고 **거동**으로 묻도록 바꿨다. 두 칸이 함께 서야 통과다.

| 칸 | 요구 | 실측 |
|---|---|---|
| 양성 | 세션을 만들고(`POST /api/sessions` → `sessionId`) 그 세션으로 `GET /api/scenarios` | **200** |
| 음성 | 세션 **없이** 같은 경로 | **401** |

```
   ai-api 깊은 검사      GET /api/scenarios 세션 있음 -> 200 · 세션 없음 -> 401
rc 0 · 17 passed (8.4s)
```

- 🔴 **문을 양면으로 시험한다.** 「전부 200 을 돌려주는 얕은 스텁」은 음성 칸에서 걸리고, 「전부 401 을 돌려주는 문」은 양성 칸에서 걸린다. 앞판의 한 칸(경로 수)보다 넓어진 게 아니라 **주어가 대상의 거동으로 옮겨졌다**.
- 前後 대조가 이 교체의 근거다: **前 = 0본 실행(throw) · 後 = 17 passed**. 같은 무대, 같은 명령, 바뀐 것은 preflight 한 파일뿐이다.

## 2. 리셋 실패 갈래 — 서버가 실패하면 키가 남는다 (E1)

처방은 「서버가 성공한 회차에만 지운다」고 적혀 있다. 그 말이 참인지, **실패를 만들어** 물었다. 자극은 브라우저에서 `POST /api/sessions/*/reset` 을 가로채 **500** 으로 답하는 것이다.

🔴 **성공 갈래를 같은 실행의 음성 칸으로 두었다.** 실패 쪽만 보면 「아무것도 안 지우는 리셋」도 초록이 된다.

| 칸 | 실측 | 기대 | 판정 |
|---|---|---|---|
| 자극 실재 | intercepted=**1** | >=1 | PASS |
| 실패 / 안내 키 | **1 -> 1** | 보존 | PASS |
| 실패 / 투어 키 | **set -> set** | 보존 | PASS |
| 실패 / 화면 문면 | 「초기화하지 못했습니다」 **표시됨** | 실패를 말한다 | PASS |
| 성공 / 안내 키 | **1 -> 0** | 삭제 | PASS |
| 성공 / 투어 키 | **set -> null** | 삭제 | PASS |

`cells=6 fail=0`

- 🔴 **자극 실재 칸**을 따로 둔 이유: 가로채기가 0건이면 「실패 갈래」 열은 **아무것도 강제하지 않은 채** 초록이 된다. 그 칸이 1 이어야 나머지 다섯 칸에 뜻이 생긴다.
- **자극 열을 먼저 돌렸다.** 성공 열을 앞에 두면 그 열이 상태를 지우고 시작해 실패 열의 「보존」이 무의미해진다.

그물 = `tests/web/tour_reset_failure_branch.mjs`.

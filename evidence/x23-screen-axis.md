## 2. 화면 축 측정 — 같은 그물 · 같은 질문 · 세 열

질문은 **지어내지 않고 화면이 준 승인 목록**에서 골랐다(`Q-MULTIHOP-001` · 화면이 제시한 선택지 **10개**).
승인 목록 밖 질문은 `app/retrieval/service.py:70` 이 **400** 으로 거절하므로 질문 쪽으로는 상태를 못 만든다.

| 열 | 무대 | 열 수 | graphrag hits | graphrag **근거 ID 링크** | 「결과를 내지 않았습니다」 **보임** | vector/hybrid hits | console error | page error |
|---|---|---|---|---|---|---|---|---|
| **B 자극** | `:8815` → `:8813` | 3 | **0** | **0** | **true** | **5 / 5** | 0 | 0 |
| **CTRL 대조군** | `:8816` → `:8190` | 3 | **5** | **5** | **false** | 5 / 5 | 0 | 0 |
| **A 오류** | `:8817` → `:8811` | **0** | — | **0**(화면 전체) | — (오류 배너) | — | 1건(=503 리소스) | 0 |

### 판정 — B 열 (정본 3항 그대로)

1. **「모른다」** — hit 0 인 graphrag 열이 `이 전략은 결과를 내지 않았습니다.` 를 **보이게** 말한다(`emptyLineVisible=true`).
2. **「지어내지 않는다」** — 그 열의 **근거 항목 0건 · 근거 ID 링크 0건**. 없는 근거를 채워 넣지 않았다.
3. **「그 사실이 화면에 보인다」** — 열 자체가 `data-strategy="graphrag"` 로 **남아 있고**(사라지지 않는다),
   차이 요약(`compare-diff`)도 그 열 기준으로 그려진다. 침묵으로 지우지 않았다.

### 🔴 이 초록이 「아무것도 못 그리는 화면」이 아님을 가르는 두 대조군

- **같은 실행 안** — vector **5** · hybrid **5**(근거 ID 링크도 각각 5). 그물은 닿았고 화면은 근거를 **그릴 줄 안다**.
  이 열이 없으면 「0 을 잘 말한다」와 「아무것도 못 그린다」가 같은 초록을 낸다.
- **손잡이 하나만 다른 무대** — 같은 그물·같은 질문·같은 셸 코드로 `:8190`(정상 그래프)을 겨누자 graphrag 가 **5**가 되고
  빈 문면이 **사라진다**. ⇒ B 열의 0 은 **그 무대의 빈 그래프가 만든 사실**이지 graphrag 열이 늘 죽어 있는 것이 아니다.

### A 열 (판정선 아님 · 1줄 병기)

`:8811`(빈 색인)을 겨눈 셸에서 같은 조작을 하면 화면은 **오류 배너를 띄운다** —
`비교하지 못했습니다. (HTTP 503 (503))` (`compare-error` **보임**) · **화면 전체 근거 항목 0건**.
⇒ 「오류가 화면에 오류로 보이고, 지어낸 근거 0」. **오류는 「검색 0건」이 아니다** — 두 상태가 화면에서도 갈린다.

🔵 **관측 1건(결함 아님 · 문면)** — 배너가 `(HTTP 503 (503))` 로 **코드를 두 번** 적는다. 판정선 밖이라 회부하지 않고 적어만 둔다.

| 축 | 왜 못 쟀나 |

| **X-23 «조사 답변» 축**(라이브 조사에서 근거 0 → 답이 「모른다」) | 이 무대는 vector/hybrid 근거가 **≥1** 이라 「**런 전체** 근거 0」 상태가 서지 않는다. 색인까지 비우면(`:8811`) 그 전에 **503** 이 나 조사 자체가 시작되지 않는다 — 「오류」와 「근거 0」은 다른 상태다 |

| **X-13**(근거가 없는 질문) | 질문 allowlist(`app/retrieval/service.py:70`)가 목록 밖 질문을 **400** 으로 거절한다 — 질문 쪽으로는 「근거 없는 질문」 상태를 못 만든다. 사유가 「원인 불명」 → **「입력 표면이 그 상태를 허용하지 않는다」**로 좁혀졌다 |
| **live cap** | 이 축은 조사 run 을 **쓰지 않았다** — cap 1 재가분 **소비 0** |

## 4. 자수 (내 계측기 · 대상 결함 아님)

1. `/compare` 를 바로 열었다가 **307 → `/`** 로 되돌려졌다. 세션 없이는 못 여는 화면이다 — 입장(`enter-button` → `waitForURL('**/overview')`)을 그물의 **전제**로 넣었다.
2. 입장 버튼이 계속 리렌더되어(`element was detached from the DOM, retrying`) 일반 클릭이 30초를 채우고 죽었다. **덮개가 아니었다**(`elementFromPoint` = 그 버튼 자신 · dialog 0) — 안정성 검사 문제라 **강제 클릭**으로 내려갔고, 어느 길로 들어갔는지(`enterPath`)를 값으로 남겼다. 🔴 이 타임아웃을 「대상 결함」으로 옮기지 않았다.
3. 처음엔 결과 열만 기다려서 **A 열(오류 무대)에서 타임아웃**이 날 그물이었다. 두 갈래(`compare-columns` / `compare-error`)를 **둘 다** 기다리게 고쳤다 — 오류 무대의 타임아웃은 화면의 답이 아니라 내 그물의 답이다.
4. 그물 문자열에 실제 개행이 섞여 **JS 파싱 단계에서 죽었다**(내 패치 실수). 산출물이 비어 나온 것을 「측정 실패」로 적지 않고 고쳐 다시 쟀다.
5. playwright 를 **다른 워크트리**의 `node_modules` 로 풀려 했다 — 메인 체크아웃의 `tests/web/node_modules` 는 **0개**였다. 남의 트리에 도구를 묶지 않으려고 **내 lane 에 `npm ci`** 를 돌려 그 위에서 다시 쟀다(현재 측정치는 전부 내 lane 설치 기준).
6. `:8190` 을 「상시 셸 무대」로 알고 그물을 겨눴다가 **404** 를 맞았다 — 전언이 가리킨 것은 API 였다(§1 정정 1).

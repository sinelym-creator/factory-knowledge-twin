## §2 AC② 「편집 = title·parts · PATCH 자동 저장 · 새로고침 일치」 = **PASS + D-5 개방**

### 2.1 값 축 — 전건 PASS

| 무엇 | 실측 |
|---|---|
| 디바운스 | 글자를 연속 입력(40ms 간격) → **PATCH 정확히 1건** · 본문 = `{title:"…"}` **단독**(다른 키 0) |
| 자극 실재 | PATCH 계수 > 0 을 먼저 확인 — 0이면 어느 색도 내지 않는다(0건 아님) |
| 저장 표시 | `wo-save-state[data-changes]="1"` · 문면 「변경 1건 · 자동 저장됨」 |
| 새로고침 일치 | 서버 `title` = 새 값 · reload 후 입력 칸 값 = 새 값 |
| parts 추가 | PATCH 1건 · 본문 `parts` 길이 = n+1 · **신규 원소에 `componentId` 키 없음**(지어내지 않았다) · 화면 「(신규)」 |
| parts 이름 저장 | blur → PATCH → 서버 마지막 원소 `name` 일치 · reload 후 표시 일치 |
| parts 삭제 | PATCH → 서버 길이 복귀 · reload 후 화면 수 복귀 |

🔴 **신규 부품 id 무생성**은 값 축의 핵심이다 — 온톨로지 id 를 지어 붙이면 그 id 는 아무 데도
열리지 않는 「없는 근거」가 된다. 요청 본문으로 확인했다(화면 문면이 아니라).

### 2.2 🔴 표시 축 — **D-5**(아래 §8)

「신규 2건 중 **앞**을 지운다」에서 화면과 서버가 갈렸다. 값은 옳고 표시가 밀렸다.

## §3 AC③ 「R12 잠금 · 403 사유 코드 = 문구」 = **PASS**

### 3.1 화면 축

| 무엇 | 실측 |
|---|---|
| `wo-procedures` 편집 칸 | **0** |
| `wo-safety` 편집 칸 | **0** |
| 세는 눈 대조군 | 같은 눈이 `wo-parts` 에서는 입력 칸 **> 0** 을 본다(0 이 「내가 못 본 0」이 아니다) |
| 안전 조치 삭제 «시도» | `wo-locked-note` 표시 · 문면 = 「안전 조치는 SOP 가 요구하는 항목이라 편집·삭제할 수 없습니다 (safety_measure_immutable)」 |
| 🔴 서버 요청 | 삭제 시도로 나간 PATCH **0건** — 화면에서 끝난다(뻔한 403 을 쏘지 않는다) |
| 🔴 조건절 | 「mandatory」·「인 경우」·「필수인 경우」·「일 때」 **전건 0** — Q-31 이 지운 조건절이 되살아나지 않았다 |
| mandatory 무관 | `wo-safety-item[data-mandatory]` 두 값이 **같은 문구**로 잠긴다(서버가 그 축으로 가르지 않으므로) |
| 절차 문구 | 「절차는 안전 조치의 «근거»라 편집할 수 없습니다」 = `safety_basis_immutable` 의 뜻 |

### 3.2 🔴 서버 대조군 — 403 사유 코드 **7종**(티켓은 3종이라 적었다)

`PATCH /work-orders/{woId}` · pending 상태 · 필드 하나씩:

| 보낸 필드 | 상태 | 코드 |
|---|---|---|
| `safetyMeasures` | 403 | `safety_measure_immutable` |
| `procedures` | 403 | `safety_basis_immutable` |
| `gaps` | 403 | `gap_notice_immutable` |
| `evidenceIds` | 403 | `evidence_basis_immutable` |
| `approvalState` · `state` | 403 | `approval_path_bypass` |
| `workOrderDraftId`·`incidentId`·`equipmentId`·`failureModeId` | 403 | `identity_immutable` |
| `note` · 모르는 키(`bogusKey`) | 403 | `field_not_editable` |

- **우선순위 실증**: `{note, safetyMeasures}` 동시 → `safety_measure_immutable`
  (안전 축이 신원·기타 축보다 먼저 말한다) · message 에는 **어긴 필드 전부**가 실린다.
- **검사 순서 실증**: 종단 상태에서 `{safetyMeasures:[]}` → 403 이 아니라 **409 `work_order_not_editable`**
  (「편집이 열려 있는가」가 「무엇을 편집해도 되는가」보다 바깥 문이다 — 서버 성문과 실물 일치).
- 허용 축: `{title:"   "}` → **422 `invalid_field_type`** · `{parts:[]}`·`{parts:[{name:""}]}` → **200**.

### 3.3 「3코드 = 3문구」의 판정

- `safety_measure_immutable` · `safety_basis_immutable` = **화면에 상시 문구 2종**(잠금 사유가
  조작 «전»에 이미 적혀 있다) + 삭제 시도 시 코드명까지 든 3번째 문장.
- `field_not_editable` = **화면에 도달 경로가 없다.** 화면이 여는 입력이 `title`·`parts` 뿐이고
  `patchWorkOrderBrowser` 의 타입이 그 둘로 좁혀져 있어, 그 코드를 부를 요청 자체가 나가지 않는다.
  🔴 이것은 **결함이 아니라 「화면이 서버보다 엄격한」 방향**이다(금지된 것은 느슨한 쪽뿐이다).
  실패 시 문구 경로는 살아 있다 — `wo-error` 가 `${message} (${code})` 로 그리며, 서버가 코드를
  가른 뜻이 화면에서 뭉개지지 않는다. **AC③ PASS**로 계수하고, 「3문구」의 뜻을
  「3코드가 뭉개지지 않는다」로 성문한다.

## §11 유언 (14대)

> **「값이 맞다」와 「화면이 그 값을 든다」는 다른 사실이다.**

> **「빨강의 주어를 세 번 물어라 — 내 도구인가, 이 티켓인가, 옆 티켓인가.」**

> 가장 조용한 오귀속이다. 산출물을 치워 보고, `git log -S` 로 커밋을 짚고,

### 1-b. build_index 계수 — 두 출처가 서로를 검증한다

| 값 | 출처 A: `build_index.py` stdout(자기 신고) | 출처 B: `index counts` DB 직접 질의 |

| chunk | `chunk 59건 / revision 45건` | **59** |

## 2. 축② — 대조군이 「같은 무대 前→後 한 변수」인가

**성립한다.** YAML step 순서 실측:

```
run ai-api (컨테이너 기동)      ← 무대는 여기서 한 번만 뜬다
대조군 — 색인 0 에서 스모크      ← 前
build index (계수 stdout)       ← 변수는 이것 하나
index counts (DB 직접 질의)
benchmark smoke (색인 후)        ← 後
```

- 「만든 뒤 지운」 순서가 아니라 **만들기 «전»에 잰** 순서다(발주 ②의 물음).
- 두 열 사이에 **컨테이너 재기동·재생성이 없다** — 같은 인스턴스가 두 열을 다 받았다.
- 대조군은 자기 전제를 스스로 확증한다: `chunks = 0` 이 아니면 `exit 1`(「색인 전인데 chunk N행 — 대조군이 성립하지 않는다」).
- 실패를 삼키지 않는 형태: `set -uo pipefail` + `node ... || rc=$?` ✔.
- **무대가 처방을 실었는가**: `/api/health` 응답의 `build` = **`9125e20a3dcc…`** = 1차 run 의 PR 커밋 → 그 컨테이너가 이 PR 의 코드다(자기 신고지만 sha 는 대조 가능).

## 7. 🔴 회부 1건 — 대조군 «前» 열의 상태코드가 관측되지 않는다 (비차단)

- **사실**: 대조군 step 은 `--out` 없이 스모크를 돌려 stdout 만 `/tmp/ctrl.txt` 로 받는다(4줄). 그래서 **前 열에는 요청별 `status` 가 없다**. 後 열만 `benchmark-smoke.json` 으로 전 행 200 을 증명한다.
- **왜 문제인가**: 「hit 0」 이 **200 + 빈 결과**인지 **비200 실패**인지 그 열에서는 가를 수 없다. 실패한 호출이 hit 0 으로 세어지면 대조군의 빨강 주어가 「색인 없음」이 아니라 「호출 실패」가 된다.
- **이번 run 의 귀속은 유지된다**(아래 셋이 받쳐 준다): ⓐ 기동 대기가 **http 200** 을 받고 진행했다 ⓑ 두 열 사이에 **컨테이너 재기동이 없다** — 後 열에서 전 행 200 을 낸 그 인스턴스가 前 열도 받았다 ⓒ 대조군 문면이 표본 10문을 **열거한 뒤** 구조 가드를 울렸다(연결 실패면 그 자리까지 못 온다).
- **처방 제안**: 대조군 step 에도 `--out /tmp/ctrl.json` 을 주고 artifact 에 얹는다. 한 줄이면 前 열도 상태코드를 갖는다.
- 등급 = **비차단**(이번 판정 PASS 유지) · 다음 회귀 때 그물이 조용히 약해지는 자리를 막는 개선.

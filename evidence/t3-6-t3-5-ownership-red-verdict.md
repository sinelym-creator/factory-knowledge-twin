# ⓑ `t3-6:199` · `t3-5:504` 빨강의 주어 — **그물 위양성**(clean DB 무관) · E1

## 🔴 먼저: 「남의 것」이 무엇으로 세어졌는가 (판정 첫 줄 · 오케 요구)

원장·발주 문면의 「남의 것 **3건**」은 **DB 행 수가 아니다**. 그물의 정의는 이렇다:

```ts
const OWNERSHIP_WORDS = ["남의", "다른 세션", "소유"];
function assertsOwnership(text) // 문장 단위로 쪼개, 위 낱말이 있고
                                // 선언지 표지(이거나·거나·또는·혹은)가 «없는» 문장을 센다
```

세는 대상 = **렌더된 페이지 본문 텍스트**(`bodyText`), 단위 = **문장**. 그리고 실측한 값은
**1건**이다 — 보고서에 적힌 「+3」은 Jest 스타일 diff 의 **줄 수**(`Array [` · 항목 · `]`)이지
항목 수가 아니다. 🔴 **세 갈래(오염/seed/제3원인)는 전부 「행 수」를 전제로 서 있었는데, 이
축은 애초에 행을 세지 않는다.**

## 판정

- **오염(ⓑ) 아님** · **seed 기준선(ⓐ 원문 형태) 아님** · **제3 원인(ⓒ)** — 정확히는
  **그물의 위양성**이다: 스캔 범위가 «셸 전체 본문»이라 앱 공용 배너의 낱말이 자원별 소유권
  단언으로 계수된다. `t3-5:504` 도 같은 원인(같은 배너의 「소유」).
- clean DB 열에서 **`t3-6:148` 이 추가로 빨강**이 됐다 — 새 결함이 아니라 **같은 위양성**이
  배너 렌더 타이밍에 따라 걸리는 자리다(공용 열에서는 그 회차에 안 걸렸을 뿐).

## 권고(내 scope · 미집행 — 발주 대기)

`bodyText` 를 **`main` 영역**으로 좁힌다(또는 `fallback-banner` 텍스트를 뺀다). 🔴 「소유자」를
통째로 예외 처리하는 방식은 **반대**한다 — 「이 문서의 소유자는 …」 같은 **진짜 누출**까지
같이 통과시킨다. 축의 주어는 「요청한 자원에 대해 화면이 소유를 단언하는가」이므로, **셸 크롬이
아니라 자원 화면**을 세는 것이 정본에 맞다.

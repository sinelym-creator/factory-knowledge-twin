## 3. 🔴 D-1 결함 — 전역 거절이 세션 몫을 먹는다

| 회차 | 상태 | 그 세션 `runCap.used` |
|---|---|---|
| 1 | 429 `live_hourly_cap_exceeded` | 0 → **1** |
| 2 | 429 | 0 → **1** |
| 3 | 429 | 0 → **1** |
| 4(전역 축 실행분) | 429 | 0 → **1** |

정본 ① = 「**어느 하나라도 거절이면 계수하지 않는다(거절은 소모가 아니다)**」.
세션 상한 거절은 이 규칙을 지키는데(§2 ①에서 used 불변), **전역 거절만 세션 카운터를 올린다**.
판정 순서가 「세션 → 전역」이라 세션 `admit` 이 먼저 카운트를 올리고, 전역에서 거절할 때 그것을 **되돌리지 않는** 형태로 보인다.

**방문자에게 무엇인가**: 전역이 소진된 한 시간 동안 조사를 시도하면 **거절당하면서 자기 세션 몫 3회를 잃는다**.
전역이 풀려도 그 세션은 이미 소진 상태다. 시도 3회면 그 세션의 Live 는 그 시간 내내 닫힌다.

## 6. 관측 회부 2

**O-1 — `429` 본문 형상이 정본 문면과 다르다(평탄 vs `detail {}`)**

```
{"error":{"code":"live_hourly_cap_exceeded","message":"…","limit":3,"used":3,"remaining":0,"retryAfterSec":3532}}
```

정본 ①ⓑ = `detail { limit, used, remaining: 0, retryAfterSec }`. 실제는 `error` 에 **평탄**하게 실린다.
🔴 다만 **세션 축(`session_run_cap_exceeded`)도 똑같이 평탄**하다(실측) — 즉 구현은 **v0.1.12 기존 형상을 그대로 따랐고**,
정본이 세션 축에 요구한 「형상 불변」과는 오히려 **일관**된다. 값은 네 개 모두 있고 `Retry-After` 헤더도 있다.
**구현 결함이라기보다 정본 문면 쪽 정정 후보**로 올린다(판정은 오케).

**O-2 — `why` 문장이 툴팁(`title`) 전용이다**

| | title 속성 |
|---|---|
| 前 | `"마지막 확인 오후 5:07:04"` |
| 後 | `"마지막 확인 오후 5:06:06 · 실시간 분석은 잠시 쉬는 중 · 17:18 에 다시 시도"` |

`until`(08:18:46Z)이 **로컬 시각 17:18** 로 정확히 표기된다. 그러나 그 문장은 **본문 텍스트에 없다**(`body.innerText` 검색 0).
🔴 같은 리포가 `run-panels.tsx:150~153` 에서 이 형태를 명시적으로 배격한다 — 「사유를 툴팁에만 넣으면 터치 기기에서는 … 그건 숨긴 것과 같다」.
정본 개정 표의 「방문자 경험 = 왜·언제가 한 줄」은 터치 기기에서 성립하지 않는다.
**단, 前에는 사유 절 자체가 없었으므로 처방이 새로 숨긴 것은 아니다**(기존 배지 표기 관행을 따른 것). 범위 판단은 오케.

## 7. 내 계측기 자수

1. **PREP 의 ⑤ 축에 구멍이 있었다.** 셸 리터럴만 훑어 「금칙어 0건」을 냈는데, 이번 렌더 실측에서 前 화면 본문에
   「게이트웨이」가 **실제로 있었다**. A 열의 0 은 「화면에 금칙어가 없다」가 아니었다. B 열(서버 문자열 관측)과 **렌더 축**을 붙여 고쳤다.
2. **1차 B 열은 28건을 냈는데 대부분이 내 드릴 파일이었다**(`tools/live_synthesis_guard_drill.py`). 넓은 축은 엄격함이 아니라 오답이다 — `app/` 으로 좁혔다.
3. **처방 이전 이미지로 무대를 열 뻔했다.** `dev-3ac2508` 로 `/live/status` 를 찍고 「`hourlyCap` 없음」을 볼 참이었다 —
   그건 대상의 답이 아니라 **내가 옛 서버에 물은 것**이다. build sha + 새 심볼 grep 으로 막았다.
4. **화면 축 1차 자극이 미성립이었다.** 밖에서 만든 run 을 브라우저가 열어 배지 0·문단 0 이 나왔다 — **run 은 세션 소유**다.
   「자극 미성립」을 「처방이 안 보인다」로 적지 않았고, 자극을 브라우저 자신의 컨텍스트로 옮겼다.
5. **접힌 `<details>` 의 `innerText` 는 `summary` 뿐이다.** 1차 값이 「details 안 = "자세히"」였다 —
   그 값으로는 「원문이 거기 있다」를 말할 수 없다. 열고 다시 읽어 원문을 확인했다.
6. **`why` 문장을 「미구현」으로 회부할 뻔했다.** 내 grep 경로(`components/*/live-status.tsx`)가 좁아
   실제 파일(`components/live-status.tsx`)을 **놓쳤다**. 없는 것이 아니라 **내가 안 본 것**이었다.
7. **폴링 창보다 짧게 기다렸다.** 3.5초 관측에서 문면 후보 0 을 봤는데 폴링 주기는 **30초**다. 40초로 늘려 값을 얻었다.

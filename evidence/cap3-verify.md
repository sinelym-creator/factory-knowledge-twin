## 3. 🔴 D-1 결함 — 전역 거절이 세션 몫을 먹는다

| 회차 | 상태 | 그 세션 `runCap.used` |
|---|---|---|
| 1 | 429 `live_hourly_cap_exceeded` | 0 → **1** |
| 2 | 429 | 0 → **1** |
| 3 | 429 | 0 → **1** |
| 4(전역 축 실행분) | 429 | 0 → **1** |

정본 ① = 「**어느 하나라도 거절이면 계수하지 않는다(거절은 소모가 아니다)**」.
세션 상한 거절은 이 규칙을 지키는데(§2 ①에서 used 불변), **전역 거절만 세션 카운터를 올린다**.
판정 순서가 「세션 → 전역」이라 세션 `admit` 이 먼저 카운트를 올리고, 전역에서 거절할 때 그것을 **되돌리지 않는** 형태로 보인다.

**방문자에게 무엇인가**: 전역이 소진된 한 시간 동안 조사를 시도하면 **거절당하면서 자기 세션 몫 3회를 잃는다**.
전역이 풀려도 그 세션은 이미 소진 상태다. 시도 3회면 그 세션의 Live 는 그 시간 내내 닫힌다.

## 6. 관측 회부 2

**O-1 — `429` 본문 형상이 정본 문면과 다르다(평탄 vs `detail {}`)**

```
{"error":{"code":"live_hourly_cap_exceeded","message":"…","limit":3,"used":3,"remaining":0,"retryAfterSec":3532}}
```

정본 ①ⓑ = `detail { limit, used, remaining: 0, retryAfterSec }`. 실제는 `error` 에 **평탄**하게 실린다.
🔴 다만 **세션 축(`session_run_cap_exceeded`)도 똑같이 평탄**하다(실측) — 즉 구현은 **v0.1.12 기존 형상을 그대로 따랐고**,
정본이 세션 축에 요구한 「형상 불변」과는 오히려 **일관**된다. 값은 네 개 모두 있고 `Retry-After` 헤더도 있다.
**구현 결함이라기보다 정본 문면 쪽 정정 후보**로 올린다(판정은 오케).

**O-2 — `why` 문장이 툴팁(`title`) 전용이다**

| | title 속성 |
|---|---|
| 前 | `"마지막 확인 오후 5:07:04"` |
| 後 | `"마지막 확인 오후 5:06:06 · 실시간 분석은 잠시 쉬는 중 · 17:18 에 다시 시도"` |

`until`(08:18:46Z)이 **로컬 시각 17:18** 로 정확히 표기된다. 그러나 그 문장은 **본문 텍스트에 없다**(`body.innerText` 검색 0).

| `hourly_cap_exhausted` | 「· 이 시간 실시간 분석 3회 사용 · **18:24** 에 다시 열림」 | **true** | 18:24 | **0건** |
| `synthesis_failing` | 「· 실시간 분석은 잠시 쉬는 중 · **17:43** 에 다시 시도」 | **true** | 17:43 | **0건** |

`until` = `2026-09-11T08:43:22Z` → 로컬 **17:43** 로 정확히 환산된다(걸쇠 축). 횟수 3 도 화면 상수가 아니라 `hourlyCap.limit` 에서 온다.

🔴 **판정선은 `body.innerText` 다.** `title` 에도 여전히 같은 문장이 있지만, 앞 창의 회부는 「**툴팁에만** 있다」였고
이번엔 본문 요소(`mode-badge-why`)가 **따로 선다** — 터치 기기에서 보인다는 뜻이다.

| 폭 | `why` 박스 | 좌표 위 요소 | 넘침 | 문서 가로 스크롤 |
|---|---|---|---|---|
| 1280 | 274×13 @ 871,19 | `span · testid=mode-badge-why` | 없음 | 없음 |

🔴 `boundingBox` 산수만으로 「겹쳤다」를 말하지 않았다 — **가운데 좌표의 `elementFromPoint`** 가 그 요소 자신을 돌려준다(덮개 없음).
412 에서 높이가 13 → 26 으로 늘었다 = **두 줄로 감싸며 레이아웃 안에 들어간다**(잘리거나 밀어내지 않는다).

## R4. 내 계측기 자수 (재검분)

1. **1차 방향 A 의 FAIL 을 대상 결함으로 적을 뻔했다.** 빨강의 `code` 를 보니 `live_hourly_cap_exceeded` —
   **내가 만들려던 자극이 아니었다**. 빨강의 주어를 먼저 묻지 않았으면 없는 결함을 회부했을 것이다.
2. **두 방향을 한 무대에서 재려 했다.** 두 상한이 같은 무대에서 함께 움직이면 어느 쪽이 거절했는지 내가 고를 수 없다 —
   손잡이를 갈라야(세션 2/전역 100, 세션 3/전역 3) 각 방향이 제 열을 갖는다.
3. **④ 배지 회귀 1차가 「안내문단 0」이었다.** 스텁이 정상 응답해 `axis=live` 였기 때문이다 — 자극 미성립이지
   처방 실종이 아니다. 스텁을 내려 `live-rejected` 를 만든 뒤 다시 쟀다.

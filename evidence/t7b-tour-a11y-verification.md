🔴 **그리고 축①이 통과한 이유가 바로 이것이다.** step6 은 **배경의** 근거 칩을 눌러야 넘어간다 —
완전한 focus trap 이면 그 칩에 Tab 이 못 닿아 **키보드 완주가 그 자리에서 죽는다.** 두 축은
독립이 아니라 **서로를 문다.** 그래서 한 표에 같이 놓는다.

### 🔴 회부 — **규격 공백 1건**

오케 설계 판정(09-03 21:14)은 「trap 경계 = **말풍선 ∪ 현재 하이라이트 대상**」이다.
**그 문장은 `t6-5-guided-tour-spec.md` 어디에도 없다.** 지금 규격이 말하는 것은 「안 막는다」(12행)와

→ **정본에 성문이 필요하다**(오케 소관). 성문 전에는 이 축에 빨강도 초록도 못 준다 —
「trap 이 없다」가 위반인지 준수인지 **정본이 아직 말한 적이 없기 때문**이다.

## 3. 축③ ARIA — 정본 명시분 **3/3 충족** · 관행 대비 부족 3곳

DOM 실독(`[data-testid="tour-callout"]`):

| 속성 | 실측 | 정본 |
|---|---|---|
| `role` | **`region`** | 41행 명시 ✅ |
| `aria-label` | **`가이드 투어`** | 41행 명시 ✅ |
| `aria-live` | **`polite`** | 41행·60행 명시 ✅ |
| `aria-modal` | **없음** | 정본 무언급 — non-modal 설계와 **정합**(넣으면 오히려 거짓말이 된다) |
| `aria-labelledby` | **없음** | 정본 무언급 |
| `aria-describedby` | **없음** | 정본 무언급 |
| `tabindex`(콜아웃) | 없음 | — |
| 스포트라이트 `aria-hidden` | **`true`** | 60행 명시 ✅ |
| 진행 표시 | 점은 `aria-hidden` **이지만 옆에 텍스트 `1/9` 가 있다** | 정보 손실 **없음** |

**관행 대비 부족 3곳**(성숙한 투어 라이브러리가 공통으로 갖는 것 · **우리 정본의 위반은 아니다**):

- **(a) 제목이 `<p tabindex="-1">` 이다** — 제목 요소(`h*`)가 아니고 `id` 도 없다. 그래서
  `aria-labelledby` 로 **콜아웃의 접근명을 스텝 제목으로 만들 수 없다.** 지금 접근명은 9단계
  내내 고정 문자열 「가이드 투어」다. (포커스가 제목으로 가므로 제목 자체는 읽히지만,
  **영역의 이름**과 **문서 개요(heading outline)**에는 스텝이 안 나타난다.)
- **(b) 본문이 `aria-describedby` 로 묶여 있지 않다** — 설명 문단이 영역의 «설명»으로 연결되지 않는다.
- **(c) 🔴 `tour-await-click` 이 대상을 «가리키지» 않는다** — 문면은 `<span>직접 눌러 보세요</span>`
  로 **포커스 불가**이고, 눌러야 할 대상과의 프로그램적 연결(`aria-controls`·`aria-describedby`·
  포커스 이동)이 **하나도 없다**. 실측상 그 대상은 **Tab 9회**째에 있다 — 보이는 사람은 하이라이트를
  보고 알지만, **키보드·스크린리더 사용자는 「무엇을」 누를지 안내받지 못하고 짐작해야 한다.**
  축①이 통과한 것은 **내가 대상을 미리 알고 있었기 때문**이다. 이건 그물이 사람보다 유리했던 자리다.

## 4. 축④ Esc — **PASS · 다만 「중단」과 「거부」가 구별되지 않는다**

| 관측 | 값 |
|---|---|
| Esc 로 닫히는가 | **true**(콜아웃 소멸) |
| 상태 before | `{"v":1,"status":"active","step":1}` |
| 상태 after | **`{"v":1,"status":"skipped","step":1}`** |
| 완료인가 중단인가 | **중단** — `done` 이 아니라 `skipped`, **step 이 보존**된다 |
| 다시 열면 | 앱바 `?` → **step2(「알람은 «울린 행»의 값이 앵커다」)로 이어서** ✅ |

🔴 **`tour-never`(「다시 보지 않기」)와의 차이 — 사실상 없다**(E2 · 코드 실독):
`onNever` 는 `{status:"skipped", step:0}` 을, Esc 는 `{status:"skipped", step:<현재>}` 를 쓴다.
**status 가 같다.** 초대 카드는 `status === "never"` 일 때만 뜨므로 **두 경우 모두 초대 카드가
영구히 사라진다.** 즉 「잠깐 끊었다」와 「다시는 보지 않겠다」가 **같은 결과**를 낳고, 재진입 경로는
앱바 `?` 하나뿐이다. 🔴 **이 축은 코드로만 읽었고 `tour-never` 를 실제로 눌러 보지는 않았다 —
E2 다.** 설계 의도인지 미분화인지는 정본에 규정이 없어 판정하지 않는다.

## 7. 자수 — 내 계측기가 먼저 틀렸다

1. 🔴 **첫 실행이 죽었다 — 내 결함이다.** 세 pass 가 **브라우저 컨텍스트를 공유**해서 pass A 가
   남긴 `fkt.tour.v1` 때문에 pass B 에서 초대 카드가 안 떴다(`status !== "never"`). 대상 결함이
   아니라 **내 그물이 자기 무대를 무너뜨린 것**이다. pass 마다 새 컨텍스트로 고쳤다.
2. **축①의 통과는 「내가 대상을 알고 있었다」는 이점을 안고 있다**(§3-c). 「Tab 으로 닿는다」는
   쟀지만 「사람이 그것을 찾아낼 수 있는가」는 **안 쟀다** — 후자는 이 그물의 축이 아니다.
3. **`tour-never` 는 코드로만 읽었다**(E2). 실제로 눌러 상태를 찍지 않았다.
4. **스크린리더 미실행** — §0. `aria-live` 의 «실제 낭독»과 포커스 이동이 겹쳐 **이중 낭독**이
   나는지는 DOM 으로 못 본다. 조건(라이브 영역 + 포커스 이동 동시)은 있으나 **결과는 안 쟀다.**
5. **1440 1벌 · chromium 1벌.** 좁은 폭에서 Tab 순서·도달 횟수가 달라지는지 **안 쟀다.**

## 1. 세는 자 — 「POST 200 줄 수」는 «만들어진 run 수»가 아니다 🔴

처방 뒤에는 **재사용 응답도 200**이다. 그래서 access log 의 `POST …/runs 200` 줄 수를 그대로
쓰면 후 세대에서 항상 2가 나온다(= 없는 결함을 만든다). 이 판정문의 계수기는

```
만들어진 run 수 = (POST …/runs 200 줄 수) − (재사용 로그 줄 수)
```

이고, 재사용 줄은 **ASCII 마커** `session=… scenario=… run=RUN-…` 로 센다(한글은 콘솔
인코딩에서 거짓 0 을 낸다). 응답을 받는 열(①②③)은 **runId 집합**이 정본이고 위 뺄셈은 교차 확인이다.

**계수기 대조군(같은 실행)** — 무대 없이 직접 1회 → 전·후 각각 `posts +1 · reuse +0 · created +1`. ✓

## 3. ④ X-16 — 창은 «이 무대의 시계»로 골랐다 🔴

발주문의 판정선 (A) = 「**비종결 창 «안»** 재시도 → run 1」. 창의 길이는 무대마다 다르다.

**창 실측(비종결 체류 · POST→terminal 관측 · 5ms 폴링)**

| | 시행 | 최단 | 쓴 간격 |
|---|---|---|---|
| 전 | 38 · 30 · 37 ms | **30ms** | 0ms · 9ms |
| 후 | 41 · 46 · 47 ms | **41ms** | 0ms · 12ms |

🔴 **발주문이 인용한 103~114ms 는 «다른 무대»의 값이다.** 이 무대에서 체류는 30~47ms 이므로
**50ms 재시도는 창 «밖»**이고, 실제로 50ms 로 친 회차는 전·후 **모두 `created +2`** 였다 —
그대로 보고했으면 «규칙의 정의»를 **X-16 FAIL** 로 오독할 뻔했다(§5 자수 ③).

**본 측정(창 «안» 두 열 + 창 «밖» 한 열)**

| 간격 | 창 | 전 `created` | 후 `created` | 자극 증인(전·후 동일) |
|---|---|---|---|---|
| 0ms(동시 · 실측 1~2ms) | «안» | **+2** | **+1** (`reuse +1`) | 상류 답함 +2 · 끊김 +2 · 클라이언트 수신 **0** |
| 9ms(전) / 12ms(후) | «안» | **+2** | **+1** (`reuse +1`) | 상류 답함 +2 · 끊김 +2 · 클라이언트 수신 **0** |
| 1000ms | «밖» | +2 | **+2** | 상류 답함 +2 · 끊김 +2 · 클라이언트 수신 **0** |

- **자극 실재 ✓** — 상류는 두 번 다 끝까지 답했고(`upstreamAnswered +2`), 그 답은 클라이언트에
  못 갔다(`dropped +2` · 수신 0건). 상류실패 0.
- **빨강 확인 ✓** — 같은 실행의 전 세대 창 «안» 열이 `+2`.
- **[X-16] PASS** — 후 세대는 창 «안» 재시도에서 run 1.
- **1000ms 열의 `+2` 는 FAIL 이 아니다** — 창 밖 재시도로 새 run 이 생기는 것은 **규칙의 정의**다(발주문 (A)). 값으로만 적는다.

## 5. 계측기 자수 (전부 «내 손»의 결함 · 대상 결함 아님)

1. **빈 배열에 `every`** — 측정 0건인데 「자극 실재 ✓」가 찍혔다(1회차). 「열이 있는가」를 먼저 묻도록 고쳤다. **못 잰 것은 0 이 아니라 «안 잼»이다.**
2. **`/api/scenarios` 에 세션을 안 줬다**(1회차 `session_required` → 시나리오 0건 → 전 열 미측정). 목록은 **대상이 부르게** 했다.
3. **blackhole 경유 요청에 세션 쿠키를 안 실었다**(2회차) — 상류는 **401** 로 답했고, 그 401 도
   `upstreamAnswered` 에는 «답함»으로 잡혔다. **자극은 실재했는데 축에는 안 닿은** 상태였고
   `created +0` 이 나왔다. 증인 계수기는 「닿았는가」를 말하지 「그 축을 밟았는가」를 말하지 않는다.
4. **로그가 재사용 줄을 «버렸다»** — stdout 이 cp949 라 메시지의 `—`(U+2014)에서
   `UnicodeEncodeError` 가 나 그 레코드가 통째로 사라졌다(`reuse +0`). grep 이 거짓 0 을 낸 게 아니라
   **쓰는 쪽이 안 썼다**. `PYTHONIOENCODING=utf-8` 로 띄워 고쳤다.
5. **남의 무대에서 잰 창(50ms)을 그대로 썼다**(3회차) — §3. 창은 **그 무대에서 실측**해 고른다.

## 6. 안 잰 것 (이름과 함께)

- **다중 워커** — uvicorn **1 워커**로만 쟀다. run 저장소가 프로세스 내부이므로 워커가 여럿이면
  같은 세션의 두 요청이 다른 워커에 떨어져 규칙이 안 걸릴 수 있다. **이 축은 미검증이다.**
- **셸/화면 축** — 사용자가 «버튼을 두 번 누르는» 길은 안 쟀다(이 판정문은 API 축).

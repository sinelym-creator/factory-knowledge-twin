> 리바이2 10대 · 2026-08-30 · **계획 문서**(측정 기록 아님 · 실행은 T3-1 가드 착지 후)

> 🔴 **이 문서는 주장을 하지 않는다.** 화면이 아직 없고 가드도 미착지다. 여기 적힌 것은
> 「무엇을 red 로 부를 것인가」이지 「무엇이 참인가」가 아니다.

## 0. 자리 판단 — `tests/e2e` 를 새로 파지 않았다

발주문은 `tests/e2e` 골격을 말했으나, 이 리포에는 **T1-9가 세운 `tests/web/e2e` 가 이미 있다**
(playwright 설정 · `preflight.ts` · 기존 spec 4종). 새 뿌리를 파면 ⓐ 설정·의존이 둘로 갈리고
ⓑ 「서버를 검사기가 띄우지 않는다」·「대상의 의존을 빌려 쓰지 않는다」는 그 자산의 규율을
새 뿌리가 다시 발명해야 한다. 그래서 **기존 자산을 잇는다** — 파일 관리 표준의 중복 금지와도
같은 방향이다. (발주문 「구성은 네 판단」에 따른 판단 · 이유를 여기 성문한다.)

## 1. 무엇을 브라우저로만 잴 수 있는가

API 층에서 이미 잰 것을 브라우저로 다시 재는 것은 «중복»이지 통합이 아니다. 축을 가른다.

| §21 증거 | API 층에서 «이미» 잰 것(T2-6) | 🔴 브라우저에서만 보이는 것 |
|---|---|---|
| ① API contract test | 표면 존재·오류 형상·응답 필드(라우트별 드릴) | 화면이 **그 계약대로 소비하는가** — 필드명 오독·조용한 빈 값은 렌더에서만 드러난다 |
| ② GS integration test | 서버 연쇄 13행(`gs01_integration_drill`) | **사람이 밟는 경로**의 연쇄 — 클릭으로 이어지는가, 중간 상태(로딩·부분 실패)가 다음 화면의 입력을 깨뜨리지 않는가 |
| ③ 3전략 동일 질문 | 세 축이 같은 질문 1개를 받고 각각 hits 를 냈다 | 화면이 **세 숫자를 나란히 놓고 크기를 견주는가** — Q-17(전략 간 비교 무의미)의 위반은 UI에서만 난다 |
| ④ evidence↔원문 일치 | `body[start:end] == text` 불일치 0 | **강조가 그 문장 위에 그려지는가** — 좌표가 맞아도 렌더가 어긋나면 인용은 거짓이 된다 |

🔴 ③·④가 이 계획의 본론이다. 둘 다 **서버는 옳은데 화면이 배신할 수 있는** 자리다.

## 2. red 정의 (착지 후 이 문장들로 판정한다)

| 축 | red |
|---|---|
| E-1 세션 가드 | 쿠키 없이 보호 화면 진입 → 세션 없이 **내용이 보인다** · 또는 가드 홉 뒤에 세션이 **안 생긴다**(307만 보고 초록 금지 — 기존 `session-guard.spec.ts` 계보) |
| E-2 연쇄 | 조사 실행 → 근거 열람 → WO 승인이 **클릭으로 이어지지 않는다**(id 를 손으로 옮겨야 이어지면 통합이 아니다) |
| E-3 전략 비교 | 세 전략의 `score` 를 **같은 축에 놓고 크기 비교**로 보여 준다(막대 길이·정렬·「가장 높은」 라벨) — Q-17 위반 |
| E-4 인용 강조 | 강조 구간이 evidence 원문과 **다른 문장** 위에 있다 · 또는 좌표가 없는데 **그럴듯한 위치**를 그린다 |
| E-5 R12 | 화면에서 안전 조치를 **지울 수 있다**(서버가 막아도, UI가 성공한 것처럼 말하면 red — T2-5 «침묵» 계보) |
| E-6 배지 | Live/Replay 배지가 **두 축의 조합**(v0.1.3)이 아니라 한 축만 보고 말한다 |

## 3. 실행 조건과 «건너뜀»의 뜻

- 실행 = **T3-1 세션 가드 착지 + Phase 3 화면 착지** 후. 그 전에는 spec 이 `skip` 한다.
- 🔴 **`skip` 은 초록이 아니다.** playwright 리포트의 skip 행은 「아직 안 쟀다」이며,
  판정문에 초록으로 옮겨 적지 않는다(전임 계보 「건너뛴 행은 초록으로 세지 않는다」).
- 측정 조건은 `preflight.ts` 가 매 실행 찍는다 — 어느 백엔드 상태에서 난 초록인지를
  보고서가 스스로 말하게 한다(T1-9 규율 계승).

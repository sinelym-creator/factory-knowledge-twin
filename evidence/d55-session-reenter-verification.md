## 3. 오케 힌트에 대한 답 — 「어느 요청이 401 을 받아 패널을 그리는가」

**서버 렌더 fetch 다.** `apps/web-console/app/overview/page.tsx` 는 서버 컴포넌트로 `cookies()` 를 읽어
`apiGetServer(...)` 를 부르고, 실패하면 `<Unavailable why={…}>` 를 그린다(`components/unavailable.tsx:62` 가 `data-why` 를 찍는다).
⇒ **패널은 브라우저 네트워크 면에 흔적을 안 남긴다.** 내가 1차 예행에서 대조군이 «안 깨진» 것으로 본 것은
**`/api/` 응답만 보고 있었기 때문**이고(§4 자수 2), 문서 응답까지 담자 **B 열에서 `data-why="HTTP 401"` 가 정상적으로 잡혔다.**
🔴 폐하 실물(문서 200 · 안쪽 패널만 401)과 내 curl(문서 307)이 갈린 것도 같은 층 차이다 — **문서는 서고, 그 안의 서버 fetch 가 401 을 받는다.**

## 4. 내 계측기 자수

1. 🔴 **축⑥ 감시자가 죽었는데 초록도 빨강도 아닌 «0» 을 냈다.** `addInitScript` 로 심은 MutationObserver 가
   `window.__mk` 객체는 돌려줬는데(**스크립트는 돌았다**) `seen` 집합이 **비어 있다** — 같은 화면에서 별도 `evaluate` 는
   `data-why`·`data-kind`·`data-mode` 를 **정상으로 집었다.** 두 관측이 모순이므로 이 계수는 **못 쓴다.**
   ⇒ 「되살리는 중」 표지 0건은 **「없다」가 아니라 「못 쟀다」**. 센쿠2 자수 2 재현 축은 **미완**이다.
2. 1차 예행에서 `page.on("response")` 가 **`/api/` 만** 담아 서버 렌더 401 을 한 줄도 못 봤다 — 문서 응답까지 담도록 고쳤다.
3. 1차 예행에서 쿠키를 **이름만** 비교해 「같은 이름의 새 쿠키」를 못 봤다 — **값**으로 비교하도록 고쳤다.
4. 재기동 «직후» 첫 `fetch` 가 **ECONNRESET** 을 냈다. keep-alive 소켓이 죽은 프로세스를 가리킨 것으로,
   **대상의 답이 아니라 내 커넥션 풀의 빨강**이다. `connection: close` + 3회 재시도로 고쳤다.
5. ai-api 를 **오케 전용 메인 체크아웃의 venv 인터프리터**로 띄웠다(내 워크트리에 venv 없음) — 의존성이 걸리는 축이면 이 열은 무효다.
6. 표본 **각 열 1회** · 1440×900 · chromium · 로컬 무대. 공개면 재현은 안 했다.

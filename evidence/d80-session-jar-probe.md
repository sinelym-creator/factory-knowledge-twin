그래서 **손잡이 하나(쿠키 항아리)만 다른 두 열**을 세웠다. 🔴 자극 열을 먼저 돌렸다 — 대조군을 먼저 돌리면

**같은 run · 같은 시각 · 다른 것은 쿠키 항아리 하나뿐이다.** A 는 전건 200, B 는 전건 404 —
그 404 의 주어는 **조회하는 세션**이지 코드가 아니다.

## 2. 판정

- **D-80 종결** — 이전 프로브의 404 는 **요청마다 새 세션을 발급해 남의 run 을 조회한 결과**이며,
  이는 계약 v0.1.6 의 **존재 은닉이 의도대로 동작한 것**이다. 처방 ⓐ(코드 축) **불요**.
- **부수 확인** — `mode:"replay"` run 은 즉시 `completed` 로 서고 `/events` 가 **38건**을 낸다
  (같은 세션에서). live cap **소모 0**.

## 3. 이 판정이 «못» 말하는 것 (범위)

- `_run_or_404` 가 세 갈래를 한 404 로 내므로, **B 열의 404 가 「남의 것이라서」임을 응답 문면이
  직접 말하지는 않는다.** 귀속은 **손잡이 하나만 다른 A/B 대조**에서 온다 — 문면이 아니라 설계다.
- 세션 **만료·리셋**으로 인한 404 는 이 창에서 시험하지 않았다(쿠키를 버린 열만 세웠다).
- 자수 1: 1차 실행에서 시나리오 id 추출이 빈 문자열이라 이후 요청이 `/api/scenarios//runs` 로 나가
  404·307 을 냈다 — **대상의 값이 아니라 내 스크립트의 값**이었다. 지금은 목록을 못 읽으면
  색을 내지 않고 `exit 2` 로 멈춘다(계측 실패를 빨강으로 팔지 않는다).

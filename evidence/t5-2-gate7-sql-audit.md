## 1. 검출력 — 심은 대조 1건으로 «그물이 산다»를 먼저 봤다

측정 전에 `app/_audit_control.py` 에 두 형태를 심었다: 실행 호출의 첫 인자를 f-string 으로 조립한
것 1건, SQL 상수를 f-string 으로 조립한 것 1건.

```
대조 심은 뒤 : 훑은 파일 48 · 실행 호출 43 · 동적 조립 6   (+1 검출)
               SQL 문자열 상수 29 · f-string 보간 4        (+1 검출)
대조 제거 뒤 : 훑은 파일 47 · 실행 호출 42 · 동적 조립 5
               SQL 문자열 상수 28 · f-string 보간 3
```
→ 두 감사기 모두 **심은 것을 실제로 집었다**. 그 뒤의 수를 값으로 쓴다. 대조 파일은 제거했고
작업 트리에 잔여 0.

🔴 **1차 감사기의 시야가 좁았던 것도 여기서 드러났다**: 실행 호출의 «첫 인자»만 보면, 모듈 상수에
f-string 으로 조립해 두고 변수로 넘기는 자리가 「리터럴/변수」로 보인다. 그래서 2차 감사기
(상수 축)를 따로 세웠고, 아래 §3 의 3건은 **1차에서는 보이지 않던 것**이다.

## 4. 단위 그물 — `tests_unit/test_sql_identifier_guard.py`(15 케이스)

DB 없이 돈다. 판정선은 「질의가 무엇을 돌려주는가」가 아니라 **「질의가 조립되는가」**다.

- 적대 입력 12종(`' OR 1=1 --` · `'; DROP TABLE equipment; --` · **정상 prefix 로 시작하는 변종** ·
  `$1` · `$1; SELECT 1` · 테이블 이름 그대로 · `U+202E` 방향 제어 · `NUL` · 개행 · 빈 문자열 ·
  `-` · 소문자) → **전부 `None`**.
- 🔴 **대조군**: `EQ-CNC-204 → equipment` · `SAF-LOTO-01 → safety_rule`. 이것이 없으면 「늘 None 을
  내는 함수」도 위 12건을 통과시킨다.
- 조회 결과 집합이 화이트리스트 **값과 정확히 같음** + 전부 `isidentifier()`.
- `split('-',1)` 이 첫 토막만 본다 = `EQ-'; DROP …` 도 테이블 선택을 못 바꾼다. 🔴 이 케이스가
  지키는 것은 「테이블 이름이 안 바뀐다」이지 「이 입력이 안전하다」가 아니다 — 뒤쪽 전체는 `$1` 로 간다.

**known-true**: `table_of` 를 「모르는 prefix 면 입력을 그대로 이름으로」로 고장 내니 **11 빨강** ·
되돌리니 **123 passed**(스위트 전체). 🔴 되돌린 «뒤»에도 11 빨강이 유지되는 구간이 있었는데,
원인은 **`__pycache__` 가 깨진 판을 계속 내준 것**이었다(`python -B` 는 «쓰기»만 막는다). 캐시를
지우고서야 복원이 값이 됐다 — 복원의 초록도 계측기가 최신인지 먼저 봐야 한다.

## 5. 안 잰 것 (그대로 남는다)

- **런타임 도달 관측 0** — allowlist 앞문 400 은 여전히 앞문의 사실이고, SQL 계층이 실제 입력에
  어떻게 답하는지는 **관측하지 않았다**. 정적 감사는 그 칸을 채우지 않는다.
- **마이그레이션 SQL·`db/` 스크립트·`tools/`** 는 이번 모집단 밖(`app/**` 만 훑었다).

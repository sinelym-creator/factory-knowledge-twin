## 2. 축 ① 코드 직독 (E1 · 병합 실물)

읽은 파일 = `services/ai-api/app/investigation/{events.py,live_synthesis.py,workflow.py}`(worktree HEAD `3ac2508`).

1. **발행 함수** — `events.py` `evidence_flagged(items)` → `_emit("evidence.flagged", {"items": items})`. 봉투 형상은 계약 v0.2.3 문면과 같은 모양(`type` + `payload.items`).
2. **자리** — `live_synthesis.synthesize()` 안, **`for attempt in (1, 2)` 루프 «밖»**. D-84 재요청 갈래(최대 2회차)를 타도 호출부는 한 번만 지난다.
3. **0건 규율** — `flagged = flag_evidence_text(evidence_text)` 뒤 `if flagged:` 로 감싼다. 빈 dict 는 falsy 이므로 표지 0건이면 **호출 자체가 없다**(빈 `items` 가 스키마 FAIL 인 것과 짝).
4. **배선** — `workflow.py:376 on_flagged=ctx.emitter.evidence_flagged`. 콜백이 `None` 이면 발행 층 전체가 죽는데(`if on_flagged is not None`), 그 갈래는 이 배선이 막는다.
5. 🔴 **「표지한 것 = 보낸 것」의 구조 근거** — 이벤트는 `evidence_text` 로 재고, `_request_body` 는 **같은 `evidence_text`** 로 `flag_evidence_text` 를 다시 부른다. 절단(`[:_MAX_EXCERPT]`)은 그 **위쪽** `build_evidence_text` 에서 이미 끝나 있으므로, 두 축이 보는 문자열은 같은 값이다. → **절단이 사이에 끼어 두 값이 갈리는 경로는 이 코드 형상에서 열려 있지 않다**(코드 축 소견 · 실행으로 확인은 미측).

## 3. 반증 가능한 예측 (다음 대의 대조군)

코드 축만으로 낸 진단이므로, **먼저 선언한다**. 다음 실행이 이 예측을 배반하면 진단이 틀린 것이다.

- **P1** 표지 ≥1 인 입력에서 `on_flagged` 호출 = **정확히 1회**, 같은 run 의 `_post` 호출이 2회여도 1회.
- **P2** 표지 0건 입력에서 `on_flagged` 호출 = **0회**(빈 배열조차 오지 않는다).
- **P3** 같은 입력에서 **이벤트 items 를 dict 로 접은 값 == 요청 본문 `evidenceFlags`**(키·코드 순서 포함). 어긋나면 계약 v0.2.3 「두 곳이 갈리면 결함」에 걸린다.
- **P4** 발췌를 `_MAX_EXCERPT` 넘게 길게 주어 **지시문 표지가 잘려 나가는** 입력에서도 P3 은 유지된다(둘 다 절단 «후» 문자열을 보므로). P4 가 깨지면 §2-5 의 소견이 틀린 것이다.

이 넷은 **미측**이다. P1·P2 는 구현자 단위 테스트(`tests_unit/test_evidence_flagged_event.py`)가 같은 취지의 케이스를 갖고 있으나, **내가 재실행하지 않았으므로 전언**이다. P3·P4 는 그 테스트가 재지 않는 축이다.

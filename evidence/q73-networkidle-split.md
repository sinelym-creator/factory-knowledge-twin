# Q-73 — 「`networkidle` 에서 죽던 2칸」의 주어를 가른다

> 검증 좌석(리바이2 26대) · 2026-09-02 `date` 16:10~16:21 KST · 공개 셸 읽기 자극만 ·
> 컨테이너·배포 접촉 0 · 대상 = `https://factory-knowledge-twin.vercel.app`(배포 `6e1487d`)

## §0 무엇을 물었나

T3-6 창(15:04 · 열 ③ · timeout 120s · workers 2)에서 **끝까지 빨강이던 2칸**:

| 칸 | 원본 위치 | 그때의 죽은 자리 |
|---|---|---|
| 스파크라인 | `t3-2-screens.spec.ts:209` | `waiting until "networkidle"` (`/overview`) |
| 계약 밖 kind | `t3-3-evidence.spec.ts:126` | `waiting until "networkidle"` (`/evidence/GP-not-a-doc-chunk`) |

발주가 준 판정 후보는 셋 — **그물 결함**(`waitUntil` 선택) / **대상 특성**(status 폴링이 `networkidle`
을 영구 차단 · 설계상 정상일 수 있음) / **미결**. 아래 세 열이 각각 다른 것을 지킨다.

---

## §1 열 P — 🔴 **원본이 오늘은 통과한다**(대조군 · 조건 동일)

같은 그물 · 같은 조건(timeout 120s · workers 2 · retries 0) · 대기 조건 **무변**:

```
2 passed (17.8s) · rc 0
```

⇒ **15:04 의 빨강이 16:1x 에 재현되지 않는다.**
「어제 빨강을 오늘 근거로 쓰지 않는다」는 이유로 이 열을 먼저 돌렸고, 그 판단이 판정을 바꿨다.

## §2 열 Q — 사본(대기 조건만 바꿈)도 통과

바꾼 것은 **하나**: `waitUntil:"networkidle"` → `waitUntil:"load"` + **명시 셀렉터 대기**
(`sparkline` 가시 · `screen-unavailable` 가시). 원본 spec 은 **한 글자도 안 건드렸다**.

```
2 passed (22.7s) · rc 0
```

🔴 **이 초록은 아무것도 증명하지 않는다** — 원본도 같은 순간 초록이기 때문이다. 열 Q 가 뜻을 가지려면
**열 P 가 빨강이어야** 했다. 그래서 이 열은 「사본이 옳다」가 아니라 **「오늘은 둘 다 선다」**만 말한다.

## §3 열 N — 폴링을 «세었다»(가설 없이)

두 화면을 적재한 뒤 **30초 창**에서 요청을 전수 계수했다(`tests/web/_q73_netcount.mjs`).

|---|---|---|---|---|
| `/overview` | load 2,394ms · 200 | **41건** | **26,158ms** | ✅ 있음 |
| `/evidence/GP-not-a-doc-chunk` | load 2,153ms · 200 | **15건** | **28,687ms** | ✅ 있음 |

창 안 상위 URL(건수 · 간격평균):

- `/overview`: `GET /overview` 13회(210ms) · `GET /` 8회(281ms) · `GET /incidents/INC-2025-019` 3회(804ms) ·

⇒ **「status 폴링이 `networkidle` 을 영구 차단한다」는 후보는 이 실측으로 반증된다**(적어도 부하 없는 조건에서).

## §4 판정 — **후보 3 중 둘이 떨어지고, 남는 것은 «비결정»이다**

| 후보 | 결과 |
|---|---|
| 그물 결함(`waitUntil` 선택) | 🔴 **성립 안 함** — 원본이 그대로 통과한다(열 P) |
| 대상 특성(폴링이 idle 영구 차단) | 🔴 **반증** — 26~28초 조용 구간 실측(열 N) |
| **미결 → 비결정(조건 의존)** | ✅ **이것이 남는다** — 같은 그물·같은 조건에서 **15:04 빨강 · 16:1x 초록** |

**그래서 사실은 이것이다**: 이 2칸은 **flaky** 하다. 공개 셸을 외부 vantage 에서 칠 때 **어떤 시점의
조건**(지연·부하·엣지 상태)에서 `networkidle` 이 창 안에 안 들어온다. 🔴 config 의 `retries: 0` 정본
주석대로 **flaky 는 잡음이 아니라 결함**이다 — 다만 **어느 층의 결함인지는 아직 못 가른다.**

**못 잰 것(명기)**: 15:04 의 조건을 되돌릴 손잡이가 없다. 그 시점의 엣지·백엔드 상태는 재현 불가이고,
이 창에서 **부하를 만들어 재현을 시도하지 않았다**(읽기 자극만 발주). ⇒ 「빈도」와 「임계 조건」은 미측.

## §5 남기는 것 (그물 개정은 판정 뒤 별 발주)

- **사본을 정본 suite 에 남기지 않았다.** 원본이 통과하는 지금 사본은 중복 커버리지일 뿐이다.
  개정이 발주되면 그때 이 문서의 diff(2줄)를 정본에 넣는다 — 판단은 오케.
- 재현 시도가 필요하면 **부하를 손잡이로** 세운 열이 있어야 한다(워커 8 동시 + 같은 2칸).
  그건 「읽기 자극만」 범위를 넘으므로 별 발주.
- `tests/web/_q73_netcount.mjs`(이 PR 동봉)는 **화면의 폴링을 세는 계측기**다. 다음에 같은 의심이
  올라오면 가설을 세우기 전에 이걸 먼저 돌린다.

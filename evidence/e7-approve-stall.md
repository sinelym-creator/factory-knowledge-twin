# E-7 — 「승인하고 왜 멈춰있는지 모르겠네」 재현과 주어 (리바이2 60대)

- 창 = `date 15:05:26` ~ `15:11:12` · 구독 **0** · production(`:8010`·`:8787`·공개 도메인) 무접촉
- 🔴 **측정 무대와 산출 트리가 다르다**: 측정 = **`:8196` ↔ 리바이2 ↔ `_wt/levi2-load`**(pid 29036) · 산출 = `_wt/levi2-e7`
- ai-api = **전용 `:8850`**(`fkt-levi2-stub-api` · 게이트웨이 = hold 스텁 `:8858` pid 40004) — **공용 `:8020` 에는 live 를 쏘지 않았다**

## 0. 왜 전용 무대였나 (공용에서 못 한 이유 두 줄)

1. 증상 경로는 **LIVE** 다. 공용 `:8020` 은 진짜 게이트웨이를 물고 있어 **구독을 태운다** — 발주가 「구독 0」이므로 쏘지 않았다.
2. **replay 축으로는 이 화면에 닿지 못한다**(실측): replay run 의 작업지시 링크를 열면
   `501 아직 제공되지 않는 기능입니다` 화면이다. `t3-5-wo-screen` 도 `mode: "live"` 로만 이 화면을 만든다(`:67`).
   → 그래서 **hold 스텁을 가리키는 전용 ai-api**로 live 를 돌리고(Claude 호출 0) 붙잡은 합성을 거둬 완주시켰다.

## 1. 재현 — 승인 직후에 무엇이 있었나 (412×600)

| 축 | 승인 «전» | 승인 «후» |
|---|---|---|
| `wo-screen[data-state]` | `pending` | **`approved`** |
| 승인 POST | — | **200** `{"status":"approved","auditId":"AUD-ac07b619425e"}` |
| `wo-save-state` 문면 | 「변경 없음」 | **「최종 상태라 편집할 수 없습니다.」** |
| `wo-approve` 버튼 | visible · **enabled** | **visible · disabled** · `opacity 0.4` · `cursor default` · 라벨 그대로 **「승인」** |
| `wo-reject` 버튼 | visible · enabled | **visible · disabled** |
| `wo-error` | 없음 | **없음** |
| 이력 | 없음 | 「오후 3:09:47 · 승인 · `AUD-…`」 1건 |
| 화면이 주는 **다음 행동** | 근거 링크 24개 + incident 링크(승인 전과 **동일**) | **같다 — 새로 생긴 출구 0** |
| 콘솔 오류 | — | **0건** |
| 서버 run | — | `completed` · events 꼬리 `step.started, step.completed, run.completed` |

스크린샷(승인 직후 · 412×600) = 폐하 첨부와 같은 모양: 근거 id 목록 아래 「최종 상태라 편집할 수 없습니다」 + **반려·승인 버튼이 그대로 보인다**.

## 2. 판정 — 발주 ⓑ 3갈래 중

- **「승인 응답이 오류(서버 결함)」 아니다** — 200 이고 `auditId` 가 왔다. 서버는 자기 일을 했다.
- **「응답은 성공인데 화면이 안 바뀜」도 아니다** — 상태는 `pending → approved` 로 **바뀌었고** 문면·이력·잠금이 따라왔다.
- 🔴 **「설계상 그 자리가 끝 + 출구 부재」가 맞다.** 그리고 여기에 **화면 결함 한 겹**이 붙는다:

  `apps/web-console/components/work-order/wo-screen.tsx:386~404`(실물)

  ```tsx
  <button type="button" disabled={readOnly} … className="… disabled:opacity-40" data-testid="wo-reject">반려 (사유 입력)</button>
  <button type="button" disabled={readOnly} … className="fkt-btn fkt-btn-primary …"           data-testid="wo-approve">승인</button>
  ```

  승인 뒤에도 두 버튼은 **그 자리에 그 라벨로** 남고, 달라지는 것은 **투명도뿐**이다(`승인` 은 primary 채움이라 40% 에서도 «눌리는 것»처럼 읽힌다).
  화면이 말하는 유일한 변화는 **회색 문면 한 줄**(`wo-save-state`)이고, 그것은 **「편집 불가」**를 말하지 «승인됐다»를 말하지 않는다.
  → 사용자 눈에는 **「승인 버튼이 여전히 있는데 아무 일도 안 난다」**로 보인다. 폐하의 「왜 멈춰있는지 모르겠네」가 이 자리다.

## 3. 수리 제안 1줄

승인·반려가 끝나면 **그 두 버튼을 「상태 + 다음 행동」으로 바꾼다** — 예: `승인됨 · AUD-…` 배지와 **「조사로 돌아가기」/「작업지시 목록」** 한 개의 출구.
(D-91 이 문서 화면에서 이미 푼 것과 같은 형태의 문제다: **종단에서 길이 끊긴다**.)

## 4. 내 계측기 자수

1. **1차 스크린샷은 새 브라우저 문맥으로 찍어 세션이 없었다** — 그 장은 승인 화면이 아니라 열람 불가 화면이었다. 같은 세션 안에서 다시 찍었다.
2. `hold released` 가 **0 → 2** 로 실행마다 달랐다. 붙잡힘이 «내 거둠 뒤»에 온 창이 있었다는 뜻이라, **이 값으로 무대를 자랑하지 않는다** — 이번 판정이 기대는 것은 승인 POST·화면 상태·버튼 속성이고 hold 계수가 아니다.
3. **live 를 전용 무대에서만 쏘았다.** 공용 `:8020` 의 live 카운터(폐하 화면의 「조사 1/5」)는 이 측정으로 **줄지 않았다**.

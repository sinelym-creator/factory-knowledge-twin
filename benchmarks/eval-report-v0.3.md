## 3. 검색 축 4지표 — Target / Actual

🔴 **Target 열이 비어 있는 이유** — baseline §18.2 와 계획서 §2 는 **산식만** 정하고 수치 목표를 두지 않았다(§17.1 의
목표는 지연 축이다). 없는 목표를 여기서 «잠정 목표»로 지어내지 않는다. **이 실행이 첫 기준선**이고, 목표 설정은 오케·폐하 몫이다.

분모 = `required_evidence` 가 **있는** 문항. 🔴 기대가 빈 14문은 분모에서 뺐다 — 빈 집합과의 비교는 판정이 아니다.

| 전략 | Target | Actual (any) | Actual (all) | 분모 |
|---|---|---|---|---|
| `vector` | 미설정 | **4 / 26** (15.4%) | 3 / 26 | 26 |
| `hybrid` | 미설정 | **18 / 26** (69.2%) | 14 / 26 | 26 |
| `graphrag` | 미설정 | **6 / 26** (23.1%) | 3 / 26 | 26 |

- 기대 근거가 **없는 문항 14** = `Q-DIRECT-001` `Q-SIM-001` `Q-SIM-005` `Q-SIM-006` `Q-MULTIHOP-003` `Q-SAFETY-002`

- **매칭 규칙(명시)**: `hit.evidenceId` 가 기대 id 와 완전 일치하거나, 기대가 `DOC-x@rN#NNN` 형태면 **같은 문서·판의 chunk** 도 인정.

계획서 §2 의 쌍 = `Q-MULTIHOP-003` ↔ `Q-UNANS-005`(같은 사실의 앞뒤). **둘 다 `required_evidence` 가 비어 있어**

## 8. 자수 (내 계측기)

1. 🔴 **지표 4 의 첫 값은 「0 간선」이었다 — 대상이 아니라 내 정규식이었다.** 경로 구분자를 `-[REL]->` 로 가정했는데
   실물은 **`-[REL]-`** 였다. 실행기에 「간선 0건이면 `exit 2`」를 넣어 그 0 이 다시 판정으로 새지 않게 했다.
2. 🔴 **첫 참조 집합이 좁아 그래프가 틀린 것처럼 보였다.** 생각나는 13개 표만 덤프해 413 중 **59 간선이 «부재»**로 잡혔다.
   스키마의 **외래키 전수(25종 · 522행)**로 넓히자 **413/413** 이 됐다. 「정본보다 좁은 축은 엄격함이 아니라 오답」이다.
3. 🔴 **관계명 매핑이 좁아 15건이 «불일치»로 잡혔다**(`DOCUMENTED_BY`). 실물은 `safety_rule.current_revision_id` 쪽이었다.
   초록이 보고 싶어서가 아니라 **스키마 FK 가 단정해 주는 만큼만** 넓혔고, 그 뒤에도 **심은 가짜 간선은 계속 잡힌다**(검출력 보존).
4. 첫 무대 확인 때 손으로 옮겨 적은 질문 문면을 보내 **400** 을 받았다. 콘솔 mojibake 를 그대로 타이핑한 것이다 —
   이후 질문은 파일·`/api/scenarios` 에서만 가져왔다. (부수적으로 그 400 이 문이 살아 있다는 첫 증거였다.)
5. 요약 JSON 을 bash 의 `/tmp` 에 쓰고 네이티브 python 으로 읽으려다 `FileNotFoundError` — 두 `/tmp` 가 다르다.
6. `scanEdges` 에서 매핑 없는 관계명을 만나면 `return` 하도록 짜, **경로의 뒷부분을 통째로 건너뛸 뻔했다**.
   `continue` 로 고쳤다(값이 나오기 «전»에 잡았다).

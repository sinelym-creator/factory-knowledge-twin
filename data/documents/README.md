# synthetic 문서 셋 (T1-3)

GS-01이 **인용하는** 문서의 원문. 파일 하나가 revision 하나이며 파일명이 그대로
`document_revision.id`다(`DOC-SOP-0014@r2.md` → `DOC-SOP-0014@r2`).

여기 없는 문서는 생성기가 템플릿으로 채운다 — 검색 모집단 역할의 배경 문서다.
적재·해시 계산은 `data/generators/documents.py`가 하고, 실행은 `pwsh data/seed.ps1`.

## 규약

- **저작권**: 전부 자작 synthetic이다. 실제 제조사의 매뉴얼 문구·규정 원문을 인용하지 않는다.
  설비 모델명(`MX-500` 등)도 가공 명칭이다.
- **개행은 LF**. `.gitattributes`가 고정하고 로더가 한 번 더 정규화한다. CRLF로 체크아웃되면
  같은 문서가 플랫폼마다 다른 `content_sha256`을 갖게 되어, 색인 신선도 판정(STALE)이
  데이터 변화가 아니라 환경 차이로 흔들린다.
- **비용을 쓰지 않는다.** 원가·단가·금액이 문서 어디에도 없어야 `Q-UNANS-001`(비용은 얼마인가)에
  「근거 없음」이 정답이 된다.
- **절 번호는 화면 체계를 따른다.** `wireframes.md` §3이 「절차 3.2·3.3 인용」으로 자리를
  가리키므로, SOP는 문서마다 같은 자리에 같은 절을 둔다.

| 절 | 내용 |
|---|---|
| `### 3.1 안전 조치` | SOP가 요구하는 SafetyRule (R12와 일치해야 한다) |
| `### 3.2 진단 기준` | 🔴 화면이 인용 강조로 띄우는 문장이 있는 절 |
| `### 3.3 필요 부품` | WorkOrder `parts[]`의 근거 |
| `### 3.4 필요 공구 및 자재` | `Q-DIRECT-002`의 「공구 전량 Recall」 채점 대상 |
| `## 4. 예상 작업 시간` | `Q-DIRECT-002`의 시간 exact 채점 대상 |

## 화면이 «그 문구 그대로» 띄우는 문장

정본 = `docs/product/wireframes.md` v0.3. 목록은 `data/generators/config.py`의
`EXPECTED_QUOTES`에 있고, **생성기 자기 점검이 매 실행 대조한다** — 문서를 손보다 문장을
잃으면 데모가 아니라 생성이 먼저 실패한다.

| revision | 문구 | 띄우는 화면 |
|---|---|---|
| `DOC-SOP-0014@r2` | 진동 RMS가 기준치의 150%를 3일 이상 초과하면 베어링 마모를 우선 의심한다. | ③ 문서 원문 탭 인용 강조 |
| `DOC-MAN-0021@r1` | 베어링 마모는 초기에 RMS가 | ② evidence 카드 |
| `DOC-MAN-0021@r1` | 진동 RMS가 | ⑤ Vector-only 1위 |
| `DOC-MRP-0087@r1` | 베어링 교체 · 2025-02-11 | ② evidence 카드 |
| `DOC-SAF-0029@r3` | 전원 차단 후 잠금·표시(LOTO) 시행 | ④ 안전 조치(삭제 불가) |
| `DOC-SAF-0030@r3` | 보호장갑·보안경 | ④ 안전 조치 PPE |

🔴 **인용 문장은 데이터에서 «참»이어야 한다.** 「기준치의 150%를 3일 이상 초과」는 기준치를
어떻게 잡느냐에 따라 참이 되기도 거짓이 되기도 한다. 실측으로 정했다:

| 기준치 | 150% | 실데이터 연속 초과 | 판정 |
|---:|---:|---:|---|
| 2.2 mm/s | 3.3 | 1.39일 | ✗ 문장이 거짓이 된다 |
| **2.0 mm/s** | **3.0** | **3.46일** | **✓** |

그래서 SOP 3.2가 「기준치 = 기저 진동값 · CNC 밀링 스핀들 2.0 mm/s」를 명시한다.
파형을 늘려 맞추는 선택지는 버렸다 — GS §2의 「최근 24h 급등」이 동결이다.

## 청크 인덱스 앵커 — 🔴 바인딩 완료 (T1-4 색인 착지 · wireframes v0.4)

`wireframes.md`의 앵커는 **더 이상 목업 자리표시자가 아니다.** 정책 동결(`chunking_policy_version=1`
= `section_sentence`/512/overlap 0) → 색인 빌드 → 실값 바인딩까지 끝났다.

### 확정 좌표 (E1 · 색인된 `document_chunk`에서 재도출 · 2026-08-29)

| revision | 동결 정책 chunk 수 | 실재 범위 | 화면 앵커 (구 → 확정) | 그 좌표가 담는 것 |
|---|---:|---|---|---|
| `DOC-MAN-0021@r1` | 8 | `#000~#007` | `#014` → **`DOC-MAN-0021@r1#004`** | Q4·Q5(베어링 마모 초기 RMS · 진동 RMS) |
| `DOC-MAN-0022@r1` | 6 | `#000~#005` | `#009` → **`DOC-MAN-0022@r1#000`** | 인용문 없는 대표 좌표 |
| `DOC-SOP-0014@r2` | 3 | `#000~#002` | `#007` → **`DOC-SOP-0014@r2#001`** | Q1~Q3(150% 3일 · 진단 기준 · 필요 부품) |
| `DOC-MRP-0087@r1` | 1 | `#000` | `#003` → **`DOC-MRP-0087@r1#000`** | Q6·Q7(베어링 교체 · 2025-02-11) |

🔴 **표기 규칙 = `{revision_id}#{NNN}` · `#NNN` ≡ `chunk_index` 동치 · 0-based · 3자리 zero-pad**
(스펙 정오표 E-4 · `#000`이 첫 chunk). 구 표기 `DOC-MAN-0021#014`처럼 `@rN`을 뗀 형태는
스펙 §3.1의 chunk id가 **아니다** — revision을 떼면 D-2(`r1`≠`r2`가 서로 다른 값을 말하는 문서)에서
「어느 판을 인용했는가」가 사라진다.

### 이전 판 수치가 왜 달랐나 (기록 · 숫자만 옮기면 어긋나 보인다)

이전 표는 `1 token ≈ 1.3자`(E3)로 환산한 값이었다. 실 토크나이저(`multilingual-e5-small`) 실측은
**1.64~1.98자/token**(평균 ~1.8)이다 — 같은 400 token이 가정보다 38% 많은 분량을 담아, chunk 수가
그만큼 적게 나온다. 이전 표의 「절 경계 400 = 14개」가 실측 8개가 된 것은 문서 결함이 아니라
**환산 정정**이다. 색인 착지로 이 표는 추정에서 실측으로 대체됐다.

### 살아 있는 규율 (바인딩이 끝나도 유효하다)

1. **분량을 앵커에 역산하지 않는다.** 400 tok에 맞춰 문서를 늘리면 정책이 바뀌는 순간 전부 어긋난다.
   문서는 「매뉴얼로서 읽히는 분량」으로 쓴다.
2. **청크 수는 정책에 2배 이상 반응한다.** 정책을 다시 열면 위 좌표는 **전부 무효**다 —
   재동결 시 색인 재빌드 후 이 표를 다시 실측으로 채우고, `wireframes.md` 갱신을 오케에 요청한다.
3. 문서를 손대면 `python -m data.generators.generate`를 **먼저** 돌린다. 인용 9건·D-2 4축·
   SOP 절 구조·MR 연도를 매 실행 대조하므로, 문장을 잃으면 데모가 아니라 생성이 먼저 실패한다.
4. 좌표를 옮겨 적지 말고 **DB에서 재도출**한다 —
   `services/indexer/verify_index.py` 가 인용 9건의 실좌표를 매 실행 다시 뽑는다.

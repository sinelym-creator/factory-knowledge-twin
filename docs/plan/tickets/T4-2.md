# T4-2 — Live 보호장치·fallback·queue (S7 · baseline §16.3 · §17.2 · §6.2)

## 목표

공개 Tunnel 뒤에 서는 ai-api가 «불특정 방문자»를 받아도 노트북이 죽지 않고, Live가 죽어도 화면이 비지 않게 한다. §16.3의 S7 필수 부분집합(결정 ③ = Turnstile 대신 «동등 보호»)을 세운다.

## 게이트

1. **정본 대조 선행** — §16.3 14항 ↔ 현 코드 대응표 중간 보고 1회: «이미 있는 것»(allowlist scenario·tool · Pydantic validation · parameterized SQL·고정 Cypher · synthetic only · egress 가드) / «없는 것»(rate limit · 동시 1~2+queue · 길이 상한 · session TTL 정리 · CORS(T4-1) · HTTPS(T4-1) · container privilege) — 없는 것만 이 티켓. 🔴 계약 오류 형상(429·413·503 queue)이 현 계약에 없으면 **회부**(오케가 append 성문 · 재계산) — 코드에서 넓히지 않는다.
2. **구현** — ⓐ Live 동시 조사 1~2(semaphore · env) + bounded queue(상한 초과 = 즉시 거절 + Replay 안내 · 큐 위치/예상 대기 응답) ⓑ run timeout(env) → `run_stopped(timeout)` 이벤트 + 안전 종료(리소스 해제 실측) + Replay 안내 ⓒ rate limit(IP + 익명 세션 · 429 + Retry-After · 정적/헬스 제외) ⓓ 요청 body·자연어 길이 상한(413/422 · 계약 형상) ⓔ session TTL 자동 정리(만료 세션 = 404 은닉 «유지» — T3-1 그물 회귀 0 · 정리 주기 env) ⓕ WS 재연결/상태 재조회(§17.2 — 끊긴 뒤 `GET /runs/{id}` 재조회로 복구 · 동일 run 이벤트 중복 처리 0) ⓖ Live 실패 시 Replay 자동 제안(§6.2 — 셸 배너가 «동작»으로 이어짐 · 빈 화면 0).
3. **자기 실측 표** — 🔴 초록 3문 선행 · 동시 3요청 → 2 실행 + 1 큐/거절(응답 형상·타이밍) · timeout 강제(env 1s) → 안전 종료 이벤트 + 프로세스 리소스 실측 · 429 형상 + Retry-After · 길이 상한 413/422 · TTL 만료 → 404 · WS 끊기 → 재연결 → 상태 복구(이벤트 중복 0) · Live 다운(ai-api kill) → 셸 Replay 제안 동작 · T3-1·T2-3 그물 회귀 0.

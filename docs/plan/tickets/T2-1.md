# T2-1 — retrieval 3전략 API (vector·hybrid·graphrag)

## 목표

동결 계약 v0.1의 retrieval 표면(`/retrieval/compare` 계열)을 501에서 해제한다 — **동일 질문 1건을 3전략(vector·hybrid·graphrag)으로 실행한 실물이 완료 증거**(원장 AC). 🔴 **본 티켓은 «retrieval만»이다** — LLM 합성(synthesize)은 T2-3이며, 여기서 Claude 호출은 0이다.

## 단계 게이트 (순서 고정)

1. **계약 표면 실독 선행** — `packages/contracts/`(🔴 v0.1 동결 · 수정 = 오케 scope)에서 retrieval 계열 라우트·요청/응답 스키마를 실독하고, 착수 «전» 해제 대상 라우트 목록을 «보고»로 올린다(`python -m tools.contract_surface` 대조 — 계약 밖 경로 exit 1). AC 문장보다 계약이 길면 계약이 이긴다(6대 계보: AC가 정본보다 짧은 자리를 먼저 찾아라).
2. **vector 전략** — T1-4 색인(`document_chunk.embedding` · chunking_policy_version=1 동결) 위 pgvector 검색 경로. 질의 임베딩은 색인과 동일 모델·차원(어긋나면 즉시 보고).
3. **hybrid 전략** — 구조화 축(SQL) + vector 결합. 결합 방식(가중·rerank 등)은 후보 실측 후 근거 병기 택일 — «잰 것»만 채택 근거다.
4. **graphrag 전략** — T1-5 Neo4j 투영(노드 309·관계 448 · R03·R07·R08·R11·R12) traversal. GS-01 4-hop 경로가 결과에 실재해야 한다.
5. **동일 질문 3전략 실행 실물** — GS-01 계열 질문 1건 최소. 각 전략 응답에 인용(chunk 좌표 = 인용 추적용 · U-1 판정: 정본 입도는 문서·revision) 포함. 실행 실물(요청·응답)을 «보고»에 병기.

## 설계 (오케 · 이것이 발주 정본)

### A. 게이트웨이 프롬프트 = 배포 산출물에서 읽는다

1. `gateway.py` — `SYSTEM_PROMPT_FILE` 을 env `SYNTHESIS_GATEWAY_PROMPT_FILE` 로 덮어쓸 수 있게(미설정 = 지금처럼 `HERE/system_prompt.txt` · 하위 호환 · 좌석 무대 무영향). `run.ps1` 에 `-PromptFile` 인자 1개(다른 인자와 같은 규율 · 인자 > env > 기본).
2. `/health` 응답에 **`promptSha256`**(파일 내용 해시 앞 12자) + **`promptPath`** 추가 — 「어느 프롬프트로 도는가」를 무대가 자기 입으로 말한다(ai-api 의 `build` 도장과 같은 형태). 🔴 이 두 값이 없으면 AC 3 을 잴 수 없다.
3. **production 산출물 디렉터리** = `~/.fkt/prod/gateway/`(리포·`_wt/` 밖 고정 경로 · D-13 규율) — 내용 = 승격 sha 의 `services/synthesis-gateway/*`(`gateway.py`·`system_prompt.txt`·`requirements.txt`·`run.ps1`) + `BUILD_SHA`(승격 sha 1줄).
4. `infra/promote-gateway.ps1 -Sha <main sha> [-Restart]` — `git show <sha>:services/synthesis-gateway/<file>` 로 위 디렉터리에 **내보내기**(워킹트리를 복사하지 않는다 — 워킹트리는 dirty 일 수 있다) → `BUILD_SHA` 기록 → `-Restart` 면 `switch.ps1 off` → `on`(production 재기동 = 배포 행위 · 승격 허가 안에서만). 내보낸 뒤 `promptSha256` 을 `git show <sha>:…/system_prompt.txt | sha256` 과 대조해 출력(rc ≠ 0 이면 불일치).
5. `infra/gw-autostart.ps1` — 지금 호스트 파일(`~/.fkt/gw-autostart.ps1` · 리포 밖)의 **리포 판**: `$repo` 대신 `~/.fkt/prod/gateway/run.ps1` 을 띄우고 `-PromptFile` 같은 디렉터리의 `system_prompt.txt`. 호스트 파일 교체 = 승격 19 집행 항목(오케 · 허가 안).

## 게이트(검증 · 리바이2)

1. **결합 해소 실측** — production 게이트웨이 재기동 뒤 `:8787 /health` 의 `promptPath` 가 `.fkt/prod/gateway/` 이고, 메인 체크아웃 `system_prompt.txt` 를 **한 줄 바꿔도**(그 뒤 원복) `promptSha256` 불변 · 호출 1건의 응답도 불변(구독 1회 · 재가 안에서). 「안 바뀐다」의 대조군 = 산출물 디렉터리 파일을 바꾸면 **바뀐다**(다시 원복).
2. **develop 스택 기동** — `develop-stage.ps1 up` rc 0 · `:8020` `online true` · `build` = `origin/develop` sha · `:8797` `promptSha256` = 그 sha 의 파일 해시 · `refresh` 2회 연속 = 세 수 불변(멱등).
3. **자동 시작 무회귀** — `gw-autostart.ps1` 리포 판을 예약 작업 경로에 두고 `switch.ps1 off` → 예약 작업 수동 트리거 → `:8787` 200 + `promptPath` 산출물 경로(라이브 ON 상시 명령 = 공백 최소 · 승격 집행 창 안에서만).
4. **production 무접촉 증명** — 게이트 2 전 과정에서 `:8010`·`:8787` 호출 계수 0(게이트웨이 로그 줄 수 전/후 동일).

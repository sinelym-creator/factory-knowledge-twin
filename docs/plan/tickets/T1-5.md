# T1-5 — Neo4j projection

> 🔴 정오(08-29 · 오케): 본문·컨텍스트의 스펙 절 번호 「§2 엔티티·§3 관계표·§5 S5」는 오기 — 실물 = **§1 Entity·§2 Relation·§6 질의 경로**. 코드(manifest.py)는 실물 번호를 따랐다(정확).

## 목표

PostgreSQL 정본에서 Neo4j 그래프를 **파생 투영**으로 세운다 — 🔴 **«삭제 후 재생성» 멱등**(baseline §8.2 · Gate 2 §32.3 — pgvector·Neo4j는 언제든 지우고 PG에서 다시 만들 수 있어야 한다). GS-01 S5의 **4-hop 경로가 실체**가 된다: `EQ-CNC-204 → CP-204-BRG-01 → FM-BRG-WEAR → SOP-BRG-INSP-014 → SAF-LOTO-01`.

## 단계 게이트 (순서 고정)

1. **투영 manifest 확정** — 스펙 §2 엔티티·§3 관계표(R01~R25)에서 **Neo4j 투영 ✅ 열 전수**를 코드 정본 manifest로 세운다(스펙 표와 1:1 대조 가능한 형태 — FROZEN_POLICY 선례). 🔴 제외 = R05(`SensorReading`)·R25(`DocumentChunk`) — **P4: 그래프에는 관계만, 시계열·본문 미투영**(투영하면 multi-hop이 죽는다).
2. **투영 빌드** — PG에서 읽어 Neo4j 적재. 삭제 후 재생성 **연속 2회 diff 0**(E1) — 대조 방식(노드·관계 계수 + 속성까지 담는 덤프)은 실측 제안 병기(T1-4 「벡터 전량 덤프」 선례: 계수만으로는 속성 흔들림을 놓친다).
3. **GS-01 S5 실측** — 스펙 §5 S5 쿼리 3종 재현(E1): ⓐ 4-hop 경로(위 5노드 실값) ⓑ `FM-BRG-WEAR -INDICATED_BY-> SN-204-VIB`(R10 `signal_pattern` 속성 포함) ⓒ 경쟁 후보 `FM-TOOL-IMB` 2순위 실재.
4. **투영 버전 기록 설계 «제안 → 오케 판정 → 적용»** — 스펙 §8.3 ⑦ `graph_projection_version`이 지금 index_build에서 NULL(=미착수가 참)이다. 버전 정본·기록 방식(004 `ontology_registry` 거울 / `index_build` 원장 선례 참조)을 **제안으로 올리고 판정 후** 적용한다. 🔴 index_build 기존 행 소급 갱신 금지(append-only) — indexer가 새 빌드부터 채우는 연동은 별도 소조각으로 회부.
5. **회귀 최소 대상 성문** — 🔴 스펙 §5 「경로 성립 조건」: **R03·R08·R11·R12가 끊기면 S5가 실패한다** — 이 4관계의 끊김을 검출하는 방식(검증 좌석이 그물로 세울 수 있는 형태)을 보고에 성문.

# T3-3 — Evidence·Documents 화면 (wireframes ③)

## 목표

근거 열람 화면을 실데이터로: evidence 상세(kind별 — doc-chunk 인용 강조 offset · record) · document 뷰(revision·hash·approval_state·STALE 배지 — Q-20의 소비처가 «화면에» 선다) · 딥링크(세션 밖 읽기 전용 — v0.1.6 예외 2라우트의 화면 실체 · Q-16 해소 축).

## 게이트

1. **정본 대조 선행** — wireframes §3(Evidence) ↔ 계약 `/evidence/{id}`·`/documents/{id}` 형상(T2-2 착지분 · v0.1.1 append). 🔴 «화면 데이터 요구 ↔ 라우트» 대응표 중간 보고 1회(T3-2 표준 — 「어느 화면 요소가 먹는가」 빈 칸 = 해제·확장 대상 아님). 신규 라우트 해제 소요는 대응표가 판정 — 예상은 0(읽기 2라우트 기해제).
2. **화면** — evidence 상세(인용 문장 강조 = offset 실값 · 원문 대조 가능 형태) · document 뷰(STALE/UNVERIFIED 배지 = `stale` boolean — Q-22 보수 매핑 성문 그대로) · 🔴 딥링크 경로 = 무세션 «열람만»(v0.1.6 예외 — 세션 화면과 딥링크 화면의 경계 명시) · 키보드 내비 기본.
3. **자기 실측 표** — 🔴 «브라우저 네트워크 축» 상설 행(쿠키 유/무 + 딥링크 무세션 200 대조) · SSR/브라우저 분리 실측 · 드릴 회귀(FKT_PYTHON 규율 · 서버 재기동 후).

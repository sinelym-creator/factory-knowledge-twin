# T1-9 — Next.js A안 셸 skeleton

## 목표

T1-0이 세운 `apps/web-console/`(Next 16.3.3 · App Router · pnpm — **실물 실재, 재생성 금지·증축만**)에 **A안(Control Room) 구조의 전역 셸 + P0 라우트 골격 + 세션 격리 기반**을 세운다. 화면 «내용»은 범위 밖이다 — 이 티켓은 P0 11항 중 **전역 셸 담당 4항(세션 격리·리셋·Live 감지·Replay fallback)의 «자리»**를 세우는 골격이다(wireframes §0).

🔴 **스타일링 확정(오케 판정)**: **Tailwind CSS 채택.** 근거 = ⓐ A안 고밀도 콘솔은 유틸리티 우선이 밀도·계층 조정에 적합 ⓑ Next App Router 공식 통합 경로 ⓒ 색·모션은 D-002 유보로 «UX 폴리시 패스»에서 확정 — 지금 디자인 시스템(컴포넌트 라이브러리) 도입은 과잉이고, Tailwind 토큰 계층이 그 유보와 정합. 설치 실측(버전 병기)은 구현 몫.

## 단계 게이트 (순서 고정)

1. **실물 확인 후 증축** — `apps/web-console` 현 골격(라우트·설정) 실측 → Tailwind 설치 실측(pnpm · 버전 병기 · dev boot 재확인 E1).
2. **AppShell** — 상단 바: 로고/내비(Overview·Incidents·Compare) · **모드 배지**(`◉ LIVE`/`◑ REPLAY` — 색+아이콘+텍스트 병행 §11.3) · **세션 칩**(sessionId 앞 4자) · **⟲ 리셋** + **fallback 배너 슬롯**(조건부 영역만). A안 3단 계층(레일→트리→카드)은 셸 레벨 구조로만 반영 — 색값 하드코딩 최소(토큰 계층 · D-002 유보 정합).
3. **라우트 골격** — wireframes §6 P0 6경로: `/`(세션 생성 후 `/overview` 리다이렉트) · `/overview` · `/incidents/[incidentId]` · `/evidence/[evidenceId]` · `/work-orders/[woId]` · `/compare` — placeholder 렌더 + 🔴 **세션 가드**: 세션 쿠키 없이 진입 시 `/`로(§6 「모든 라우트」 행).
4. **데이터 배선 스텁** — 계약 v0.1 `POST /sessions` · `GET /live/status` 앞 클라이언트 스텁(백엔드 501 구간 = 오류 아닌 «미연결» 상태 표시). 🔴 **계약 밖 fetch 경로 0** — 새 경로가 필요해 보이면 착수 전 오케 회부.
5. **시각·접근성 골격** — §10 규칙의 «자리»: 다크 기본 · 상태 = 색+아이콘(●▲■) 병행 원칙을 토큰·컴포넌트 계층으로. 🔴 chat-first 금지 — 입력창을 셸에 두지 않는다.

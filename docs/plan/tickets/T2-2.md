# T2-2 — 문서·evidence 읽기 API (+ /scenarios 귀속분)

## 목표

동결 계약 v0.1의 문서·evidence 읽기 표면(`/documents`·`/evidence`)을 501에서 해제한다 — **evidence ID ↔ source 문장 일치가 완료 증거**(원장 AC). 추가 귀속분(Q-18 확정): `GET /scenarios` 해제 — T2-1의 서비스 내 allowlist와 **단일 정본**으로 묶는다. 🔴 LLM 호출 0 · 계약 확장 0은 T2-1과 동일.

## 단계 게이트 (순서 고정)

1. **계약 표면 실독 선행** — `/documents`·`/evidence`·`/scenarios` 계열 라우트·스키마를 실독하고 해제 대상 목록·필드 구조를 «보고»로 올린 뒤 코드 진입(T2-1 게이트 1과 동일 규율). AC보다 계약이 길면 계약이 이긴다.
2. **`/scenarios`** — T2-1 allowlist(서비스 내 읽기전용)와 단일 정본화. 🔴 목록 이원화 금지 — 한쪽이 다른 쪽의 원천이어야 하며, 두 목록이 따로 자라는 구조면 설계 회부(불변식 목록 교훈).
3. **`/evidence`** — evidenceId(`{document_id}@r{N}#{NNN}` · T0-6 §3.1 · `ck_chunk_id_composition` 강제) → 원문 문장 해석 + revision/hash 표면(DB 실값 — 재계산 대조는 검증 몫).
4. **`/documents` highlight** — 인용 강조 offset 실물. offset이 원문에서 그 문장을 실제로 가리켜야 한다.
5. **STALE 배지 데이터** — `v_index_freshness` 결합. 🔴 Q-20의 울음 자리가 이 표면이다: «STALE인데 검색됨»이 배지로 보이는 자리 — 낡음 상태가 응답 데이터에 실려야 한다.

# T5-4 — 운영 runbook·장애 대응·자동 시작 (baseline §14.4 · §32.7 · §35.6)

## 목표

«데모가 서 있는 상태»를 사람 기억이 아니라 문서·스크립트로 만든다: 재부팅해도 스스로 돌아오고, 장애가 나면 대응 절차가 Gate 6 행별로 있고, 새 기기에서 README 만으로 재현된다.

## 게이트

1. **자동 시작·재부팅** — Docker(compose restart 정책 실측 — 🔴 08-31 실증: compose 는 자동 복귀 · `docker run` 계열은 Exited(255) = compose 로 승격하거나 start 절차 성문) · Tunnel 서비스 자동 시작(T4-3 ⓐ 승계) · 재부팅 후 health check 스크립트(§14.4 · ai-api `/health` + 셸 + Funnel 3층 · 🔴 Q-52 계보 = «컨테이너 healthy ≠ 의존 프로브 정상» 두 층 다 잰다) · 절전/최대 절전 끔 «확인 방법»(폐하 기기 설정은 청구만).
2. **장애 대응 절차** — Gate 6 8행(§32.7) 각각 「증상 → 확인 명령 → 대응 → 원복 확인」 4열 표(T4-4 매트릭스 «실측 결과»를 절차로 옮긴다 — 재지 않은 행은 절차화하지 않는다) · demo 중 장애 시 «Replay 로 계속» 우선 원칙(§6.2).
3. **clean environment** — 새 클론 → 1커맨드(seed → index → run · §35.6) · 씨앗 재주입 전 volume 확인 규율(「빈 DB 아님」 계보) · 검증 = «타 경로 새 클론»에서 제3자 시선 재현(T5-5 결속).

### ⑧-2 상태 모델 5상태 — §③ 의 상태 문면을 **갱신한다**(D-38 처방)

현행 4상태(`never`/`active`/`done`/`skipped`)는 **「잠깐 끊기」와 「다시 보지 않기」가 같은 `skipped` 로 접힌다** — 둘 다 초대 카드가 영구히 사라진다.

| 상태 | 뜻 | 저장 | 초대 카드 | 앱바 `?` | 재개 시 |
|---|---|---|---|---|---|
| `never` | 한 번도 안 봄 | — | **보임** | 「투어 시작」 | 1단계 |
| `running` | 진행 중 | 세션 + `lastStep` | 숨김 | 「투어 재개」 | `lastStep` |
| `dismissed` | Esc·✕·바깥 클릭 = **잠깐 끊음** | 영구 + `lastStep` | **보임**(「이어서 보기」) | 「투어 재개」 | `lastStep` |
| `suppressed` | 「다시 보지 않기」 **명시 선택** | 영구 | 숨김 | 「투어 시작」 | 1단계 |
| `completed` | 끝까지 봄 | 영구 | 숨김 | 「투어 다시 보기」 | 1단계 |

**규칙 2줄** ① 🔴 **사용자가 명시적으로 고르지 않은 것은 영구가 아니다** — Esc 는 의사 표시가 아니라 탈출 키다. ② `dismissed` 는 **단계를 기억한다**(1단계부터면 다시 끊는다).
**기존 데이터 이관** = 저장된 `skipped` 는 어느 쪽인지 알 수 없으므로 **보수적으로 `dismissed`**. 틀려도 최악이 「초대 카드가 한 번 더 뜸」이고 반대는 「영구히 못 봄」이라 **비대칭**이다.

### ⑧-3 진행 조건 선언화 — §③ `tour-steps.ts` 를 **갱신한다**(폐하 재가 09-03 ⑤)

진행 조건이 코드 세 곳에 흩어져 있다. 단계 정의 **안에만** 두고 런타임은 **한 곳**에서 해석한다.

```ts
type Step =
  | { kind: 'info';        target?: Selector; advance: 'next' }
  | { kind: 'interactive'; target: Selector;
      advance: { on: 'click' | 'change' | 'custom'; of: Selector; timeoutMs?: number };
      allowSkip: boolean }
  | { kind: 'link';        target: Selector; advance: { on: 'navigate'; to: Route } };
```

🔴 **`link` 는 09-03 22:12 추가된 세 번째 kind 다**(구현 좁수 → 오케 채택). 초안이 `info`·`interactive` 둘만 둔 것은 **오케의 누락**이다 — 9단계 중 **2단계(`start`·`done`)가 화면을 옮기는 링크**고, 문면대로 쓰면 **있는 동작이 사라진다.** 🔴 **규격이 실물보다 좁으면 구현이 규격을 어기거나 기능을 버리는 둘 중 하나를 한다** — 구현이 세 번째 길(「늘리고 사유를 남긴다」)로 왔고, 그게 옳다.

### ⑧-5 `aria-modal` — «비채택»과 그 사유 (명문화 의무)

`role="dialog"` + `aria-labelledby`/`aria-describedby` 는 **채택** · `aria-modal="true"` 는 **비채택**.
- 사유 = 우리 투어는 **비모달**이고 `interactive` 단계는 **다이얼로그 «밖»의 대상**을 눌러야 넘어간다. `aria-modal="true"` 를 붙이면 스크린리더가 그 대상을 **탐색 트리에서 지운다** — **그 자리가 죽는다.**
- 🔴 **표준을 안 따르는 이유를 규격에 남기는 것이 규칙이다.** 남기지 않으면 다음 사람이 「빠뜨린 것」으로 읽고 되돌린다.
- `info` 단계에 한해 적합하나 **⑧-4 가 재가된 «뒤»에** 함께 본다.

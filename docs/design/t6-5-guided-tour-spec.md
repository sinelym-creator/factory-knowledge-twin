## ⑧ v1.1 개정 — 판정선·상태 모델·포커스 경계 (09-03)

> **출처** 폐하 하달 2본 = `.workspace/drafts/operator-ui-resolution-guide-20260903.md`(26KB) · `operator-tour-reference-guide-20260903.md`(22KB) · **좌석 실측** = 리바이2 36대 2.4.11(PR #500) · 센쿠2 37대 자수(PR #501).
> 🔴 **두 가이드가 어긋나는 자리 1건은 «나중 것»이 이긴다** — 참고 가이드 §3.1 은 `aria-modal="true"` + 배경 `inert` 를 권했으나, 해결 가이드 §1.5 가 **명시적으로 그것을 갱신**했다(대상이 다이얼로그 «밖»에 있으면 스크린리더가 대상을 못 본다). 이 규격은 나중 것을 따른다 — ⑧-5.

### ⑧-1 판정선 = 두 열 (44 단일 자 폐기)

| 축 | AA = **합격선** | AAA = 목표 |
|---|---|---|
| 대상 크기 | **2.5.8** = 24×24 CSS px **+ 간격 예외**(대상 경계 상자 중심의 지름 24px 원이 다른 대상·다른 미달 대상의 원과 교차하지 않으면 통과) | **2.5.5** = 44×44 · **예외 없음** |
| 포커스 가림 | **2.4.11** = 포커스 받은 컴포넌트가 저작자 콘텐츠에 **완전히** 가려지지 않음 | **2.4.12** = **일부도** 안 가림 |

- 🔴 **퍼센트 문턱(「10% 미만」)은 SC 어디에도 없다 — 그것은 «우리 목표»다.** 표에서 열을 갈라 적는다.
- 🔴 **주어를 섞지 않는다** — 2.4.11 의 주어는 **「지금 포커스를 받은 컴포넌트」**이고, 겹침 측정(화면 글자 714→451)은 **「화면 전체 글자」**가 주어다. **다른 축이라 한 표에 놓지 않는다.**
- 🔴 **44 는 AAA 였다** — 「터치 미달 20→6~10」은 **AAA 미달 수**이지 AA 위반 수가 아니다. 보고 서식 = **「AA n/m · AAA n/m」 두 열** + 측정한 **열**(`pointer: coarse`/`fine` · dev/prod · 엔진)을 함께 적는다.
- 🔴 **2.5.8 의 «주어» = pointer action 을 «받는» region — `inert` 아래는 target 이 아니다**(리바이2 37대 회부 · 09-04 00:50 · **오케 오기 정정**). WCAG 2.2 용어 **target** = *"region of the display that will **accept a pointer action**"* 이고, HTML `inert` 서브트리는 **pointer event 를 받지 않는다** ⇒ **모집단에서 빠진다.** 🔴 **2.4.11 이 「포커스 자격이 없어져서」 빠지는 것과 «같은 기전»**이다 — 오케가 「대상 크기 판정에서는 여전히 센다」고 한 것은 **2.4.11 의 주어 구분을 옮겨 적으며 2.5.8 의 주어를 안 읽은 오기**다.
  · **보고 서식** — 판정 열은 **`nonInert`**, 참고로 **`all`(inert 포함)을 나란히** 싣는다. 🔴 **어느 쪽도 정답으로 접지 않고 두 수를 다 내는 것**이 이 오기를 막았다.
  · ⚠ **섞지 말 것** — 「**보이는데 안 눌린다**」는 2.5.8 이 아니라 **§⑧-4 합격조건 ③**(「`inert` 배경에 마우스로 눌리는 요소 0」)의 **반대편 축**이다.

### ⑧-2 상태 모델 5상태 — §③ 의 상태 문면을 **갱신한다**(D-38 처방)

현행 4상태(`never`/`active`/`done`/`skipped`)는 **「잠깐 끊기」와 「다시 보지 않기」가 같은 `skipped` 로 접힌다** — 둘 다 초대 카드가 영구히 사라진다.

| 상태 | 뜻 | 저장 | 초대 카드 | 앱바 `?` | 재개 시 |
|---|---|---|---|---|---|
| `never` | 한 번도 안 봄 | — | **보임** | 「투어 시작」 | 1단계 |
| `running` | 진행 중 | 세션 + `lastStep` | 숨김 | 「투어 재개」 | `lastStep` |
| `dismissed` | Esc·✕·바깥 클릭 = **잠깐 끊음** | 영구 + `lastStep` | **보임**(「이어서 보기」) | 「투어 재개」 | `lastStep` |
| `suppressed` | 「다시 보지 않기」 **명시 선택** | 영구 | 숨김 | 「투어 시작」 | 1단계 |
| `completed` | 끝까지 봄 | 영구 | 숨김 | 「투어 다시 보기」 | 1단계 |

**규칙 2줄** ① 🔴 **사용자가 명시적으로 고르지 않은 것은 영구가 아니다** — Esc 는 의사 표시가 아니라 탈출 키다. ② `dismissed` 는 **단계를 기억한다**(1단계부터면 다시 끊는다).
**기존 데이터 이관** = 저장된 `skipped` 는 어느 쪽인지 알 수 없으므로 **보수적으로 `dismissed`**. 틀려도 최악이 「초대 카드가 한 번 더 뜸」이고 반대는 「영구히 못 봄」이라 **비대칭**이다.

### ⑧-3 진행 조건 선언화 — §③ `tour-steps.ts` 를 **갱신한다**(폐하 재가 09-03 ⑤)

```ts
type Step =
  | { kind: 'info';        target?: Selector; advance: 'next' }
  | { kind: 'interactive'; target: Selector;
```

- `target` 없는 `info` = **환영·마무리 카드**(중앙 · 스포트라이트 없음 · 착지 `bde30cb`).

10. 🔴 **«같은 대상»의 정체는 좌표계가 정한다 — 좌표계는 셋이다**(리바이2 37대 자수 6·7 · 09-04 01:47·06:15). ① **고정·스티키** = **뷰포트 좌표**(창이 굴러도 안 움직인다) ② **흐르는 것** = **문서 좌표** ③ 🔴 **스크롤 «조상»이 있는 것** = **콘텐츠 좌표**(`rect + 창 스크롤 + Σ 조상 scrollTop`) — 문서 좌표는 **컨테이너가 굴러가면 상태 의존**이 되어 같은 요소가 스텝마다 새 대상이 된다. **실측 = 문서 좌표만 쓰자 앱바가 스텝마다 새로 세어져 `overview` 가 16 → 36**(스텝 5 × 고정 5) · **콘텐츠 좌표로 고치자 창 스윕의 distinct 가 46 → 41.** ⇒ 한 좌표계만 쓰면 **하나를 여럿으로** 세거나 **여럿을 하나로** 접는다. 🔴 **`측정 + 안 잼 = distinct` 불변 검사가 그 감시자다** — 「안 잼이 줄었다」와 「내가 대상을 불렸다」는 **같은 모양**이라, **총계가 안 늘어야만 «발견»**이다.
11. 🔴 **그물을 옳은 방향으로 고칠 때 «옛 동작을 지우지 말고 플래그로 남겨» 매 회차 앞에서 옛 값을 재현시킨다**(리바이2 37대 · 09-04 01:33). 스윕은 모집단을 **정당하게** 바꾼다(overview 16→20). 그러면 교정 열이 전대 값을 «못 내는 게 정상»이 되어 🔴 **「산식이 갈렸다」와 「모집단이 옳아졌다」를 영원히 못 가른다.** ⇒ **교정 열만 legacy 모드로 고정**(스크롤 0 · 1회 스캔)하고 **본 측정과 한 표에 섞지 않는다.** **이 열이 하루에 두 번 값을 했다** — 폴백(⑨ · **과소**)과 중복(⑩ · **과다**)을 **각각** 잡았다.
    - 🔴 **묶는 한 줄 — 폴백은 «과소»(위반을 숨김) · 중복은 «과다»(없는 위반을 만듦). 스윕은 두 방향으로 다 틀릴 수 있었고 두 번 다 legacy 교정 열이 잡았다. 한 방향만 의심한 검증은 반대쪽에서 뚫린다.**
12. 🔴 **검증이 쓰던 «표적»을 그대로 물려쓰지 않는다 — 무대가 다르면 같은 표적이 이미 죽어 있을 수 있다**(센쿠2 37대 D-44 처방 실측 09-04 06:10). 검증 그물의 표적(「조사 시작」)은 **처방 무대에서는 모달이 없어도 안 옮겨졌다**(가짜 API). 그대로 갔으면 「모달 열림 → 이동 X」는 🔴 **처방이 아니라 «무대»가 낸 초록**이었다. ⇒ **대조군의 «생존»을 판정 «전»에 잰다** — 음성 대조(모달 닫힘)에서 표적이 **실제로 반응하는지** 먼저 확인하고, 죽어 있으면 **살아 있는 표적으로 갈아탄 뒤** 판정한다. 6규칙(「대조군도 처방과 함께 늙는다」)의 **무대 축**이다.
13. 🔴 **계측기의 «상한»도 침묵한다 — ⑨ 의 확장**(리바이2 37대 자수 7 · 09-04 06:15). 컨테이너 스윕에서 **1440 은 안 잼 15→2 인데 390 은 17→14** 밖에 안 줄어 **「좁은 폭에서는 더 못 본다」**는 **그럴듯한 서사**가 섰다. 실제로는 그 컨테이너가 **«가로» 스크롤**(`vx:true·vy:false`)이라 390 에서 띠가 여러 화면 폭이 되는데 **스텝 상한이 가로 4** 였다. **상한만 24로 올리자 측정 41/41 · 안 잼 0.** ⇒ 🔴 **한계에 걸려 멈춘 것과 거기 아무것도 없는 것이 «같은 모양»으로 보인다.** **처방 = 상한(스텝·재시도·타임아웃)을 «인자»로 빼고, 컨테이너마다 「필요한 스텝 vs 밟은 스텝」을 남기고, 잘렸으면 `truncated` 로 신고한다.**
    - 🔴 **그리고 이것이 ⑨ 계열 중 가장 위험한 형태다 — 「설명이 되는 것」과 「참인 것」은 다르고, 설명이 먼저 서면 검사가 멈춘다.** ⑨(폴백)·⑥(중복)은 **수가 이상해서** 눈에 띄었지만, 절단은 **말이 되는 서사가 이미 준비돼 있었다.** ⇒ **내 도구의 «파라미터»를 의심하기 전에 화면 탓으로 돌리지 않는다.**

### ⑧-8 말풍선 자리 — 🔴 **「대상을 덮지 않는다」가 「덜 덮는다」보다 앞선다**(D-45 · 09-04 신설)

> **왜 신설하는가** — 이 규격에는 지금까지 **「말풍선이 «지목한 대상»을 덮지 않는다」는 규정이 «없었다».** 자리 고르기가 재던 것은 **「글자를 얼마나 덮는가」뿐**이었고, 구현은 **규격대로** 그것만 했다. ⇒ 🔴 **D-45 는 「구현이 규격을 어긴 것」이 아니라 「규격이 실물보다 좁았던 것」이다** — **D-43 과 같은 계보**(규격이 실물보다 좁으면 구현은 규격을 어기거나 기능을 버린다).

1. 🔴 **경성 조건 — 말풍선은 «지목한 대상»을 덮지 않는다.** 이것이 **「글자를 덜 덮는다」보다 «앞선다».** 두 조건이 갈리면 **대상을 안 덮는 자리를 고른다.**
2. 🔴 **후보 집합은 좌·우 둘로는 부족하다** — 대상이 **화면 끝에 붙으면 두 후보가 같은 값으로 클램프**되어 **후보가 사실상 하나**가 된다(실측: 6걸음 중 **2·3·5번째가 그 상태** · 5번째는 `beside` 1436 → 상한 **1068** 로 눌려 `anchor` 와 **40px 차** · 덮은 넓이 **비율 1.000**). ⇒ 🔴 **비율이 1.000 이면 «어떤 문턱도» 못 뒤집는다. 문턱 조정은 이 문제의 처방이 아니다.**
3. **대상을 안 덮는 자리가 하나도 없는 경우의 처리를 «정하고 값으로 남긴다»** — 그런 경우가 실제로 있는지도 함께 잰다. **없으면 「없다」가 값이다.**
4. 🔴 **「한 걸음이 안 덮는다」를 「규칙이 듣는다」로 읽지 않는다** — 4번째 걸음이 대상을 안 덮은 것은 **규칙이 낸 결과가 아니라 «그 걸음의 배치»가 낸 결과**였다(대상이 왼쪽에 있고 옆에 자리가 있었다). **처방 효과를 걸음 하나로 귀속하면 «우연히 맞은 자리»를 성공으로 센다.**
5. **판정은 «밟은 걸음 안에서»만 낸다** — 사람이 눌러야 넘어가는 걸음 뒤는 자동으로 못 밟는다. 🔴 **그리고 프로브 루프의 «회차»는 걸음 수가 아니다** — 같은 자리를 다시 읽은 회차도 회차로 셈된다(실측: 루프가 4회 더 돌았지만 제목·좌표·넓이가 전부 동일 = **같은 걸음 재독**). ⇒ **「9걸음 밟았다」로 잘못 적히는 자리다.**

🔴 **이 절이 선 근거 = 화면이 스스로 남긴 값**(`data-tour-placement`·`data-tour-covered`). **오버레이가 자기 결정을 DOM 에 기록하고 있었으므로 후보와 탈락 사유를 «추측 없이» 읽었다**(E1). ⇒ **성문 — 「자기 결정을 값으로 남기는 구현은 원인 규명을 «추측»에서 «독해»로 바꾼다.」**
6. 🔴 **말풍선은 «대상에 인접한» 후보 중에서 고른다 — 인접 후보에 안 덮는 자리가 없을 때만 먼 자리를 쓴다**(센쿠2 38대가 **구현 «전»에** 잡은 구멍 · 09-04 06:47). 규칙 1(「덮지 않는다」)만 적으면 **5번째 걸음에서 `left=12`(덮음 312)가 «최적»으로 뽑히는데 대상은 `x=1028`** 이다 ⇒ **가리키는 것에서 1,000px 떨어진 자리.** 🔴 **그건 「안 덮는」 안내이지 «안내»가 아니다.** ⇒ **「덮지 않는다」와 「곁에 선다」는 «둘 다» 조건이고, 곁이 먼저다.**
   - 🔴 **성문 — 규격에 «금지»만 적고 «목적»을 안 적으면, 문면대로 구현한 것이 기능을 죽인다.** 이 절의 목적은 **「대상을 가리키는 것」**이고 덮지 않는 것은 그 수단이다.
7. **자기 결정을 값으로 남긴다** — `data-tour-placement`(고른 쪽) · `data-tour-covered`(덮은 넓이) · 🔴 **`data-tour-clear`(안 덮는 후보가 있었는가)**. ⇒ **「안 덮는 후보가 하나도 없는 경우」가 «실제로 나는지»를 셀 수 있게 된다.**
   - 🔴 **성문 — 자기 결정을 값으로 남기는 구현은 원인 규명을 «추측»에서 «독해»로 바꾼다.** D-45 원인이 하루 만에 확정된 것은 오버레이가 이미 자기 선택을 DOM 에 적고 있었기 때문이다.

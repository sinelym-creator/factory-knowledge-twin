# 재부팅 시험 절차서 — 자가 복구 완전 양성 대조

> 스자쿠 63대 작성(2026-09-22 · **폐하 재가 전 · 집행 금지**). O-59 의 남은 미측 3축을 한 번에 증명하고, 같은 창에서 O-57·O-58 을 함께 처리하기 위한 순서표.
> 🔴 이 문서는 **승인 시 그대로 따라 읽는 대본**이다. 즉흥 판단을 줄이는 것이 목적이다.

## 0. 왜 재부팅인가

health watch 의 복구 분기는 지금까지 **컨테이너 축만** 실측됐다(O-59 부분 증명 09-22 23:30). 남은 셋 — ① Docker 데몬 기동 ② health 대기 ③ 게이트웨이 위임 — 은 **전체가 죽어야** 재진다. 재부팅이 그 상태를 **안전하게·의도적으로** 만든다(전원 사고와 달리 시각을 우리가 정한다).

## 1. 전제 · 금지

- **창**: 크리덴셜 회전 창(다음 06:34:15~06:54:15) **밖**에서만.
- 폐하 재가 없으면 집행 0. 재가는 ①②③ 묶음 단위로 받는다.
- 공개 사이트(Vercel)는 이 PC 와 무관하므로 **재부팅 중에도 화면은 뜬다** — 다만 조사·AI 경로는 멈춘다. 이 비대칭을 보고에 적는다.

## 2. 前 칸(재부팅 «전»에 반드시 찍는다)

| 축 | 명령 | 적을 값 |
|---|---|---|
| 조사 서버 | `GET :8010/api/health` | `ok` · `build` |
| 게이트웨이 | `GET :8787/health` | 응답 형태(토큰 없으면 거절 = 정상) · **pid · 시작 시각** |
| 컨테이너 3본 | `docker inspect` | `Running` · `StartedAt` |
| 색인 | `psql -U fkt -d fkt` | `document_chunk` 계수(= 59) |
| 공개면 | `GET /` | 상태코드 · 소요 |
| 예약 작업 2본 | `Get-ScheduledTaskInfo` | `LastRunTime` · `LastTaskResult` |
| 라이브 | `GET /api/live/status` | `online` |

🔴 **前 칸이 없으면 後 칸은 아무것도 증명하지 않는다.** 「빈 집합과의 비교는 비교가 아니다」.

## 3. 같은 창에서 함께 처리할 2건

- **O-57**(배터리 제외): `Set-ScheduledTask` 로 `DisallowStartIfOnBatteries=$false`. 재부팅 «전»에 바꾼다(재부팅이 설정을 되돌리지 않음을 後 칸에서 확인하기 위해).
- **O-58**(토큰): `gw-autostart.ps1:54` 의 `-Token $tok` 제거 + 기동 전 `$env:SYNTHESIS_GATEWAY_TOKEN = $tok`. 🔴 **원본을 `.pre-o58` 로 보존한 뒤** 수정한다(되돌림 경로). 재부팅이 이 스크립트를 부르므로 **수정본이 곧 시험 대상**이 된다.

## 4. 집행 순서

1. 前 칸 전항 기록(§2) · 폐하께 「지금 내립니다」 1줄.
2. O-57 설정 변경 · O-58 스크립트 교체(원본 보존 확인).
3. 재부팅.
4. **손대지 않고 기다린다.** 🔴 여기서 사람이 손으로 켜면 **시험이 무효가 된다** — 자동 사슬이 스스로 하는지를 보는 것이 목적이다.
5. 복귀 관측(아래 §5). 자동 로그인 → Docker → 컨테이너 → 게이트웨이 순으로 값을 찍는다.

## 5. 後 칸 · 판정선

| 축 | 판정선 | 미달 시 |
|---|---|---|
| Docker 데몬 | 사람 개입 0 으로 UP | 🔴 O-59 ① FAIL — 자동 시작 사슬 결함 |
| 컨테이너 3본 | `Running=true` · `StartedAt` 이 재부팅 «후» | 수동 기동 후 원인 조사 |
| 조사 서버 | `/api/health` `ok` · **build 가 前 칸과 동일** | build 가 바뀌면 다른 것이 떴다는 뜻 |
| 게이트웨이 | 응답 정상 · **pid 가 前 칸과 다름**(새로 떴다는 증거) | pid 같으면 안 죽은 것 = 시험 불성립 |
| 🔴 O-58 | `Win32_Process` 명령줄에 **토큰 부재** | 되돌림(§6) |
| 🔴 라이브 | **live run 1회 완주 + 합성 호출 계수 ≥1** | 되돌림(§6) |
| O-57 | 배터리 설정 `False` 유지 | 재설정 |
| 감시 작업 | 첫 주기 실행 rc 0 | 로그 확인 |
| 색인 | `document_chunk` = 59 | 🔴 D-88 형태 — 즉시 복구 |

**총 판정** = 위 전항 통과 ⇒ O-59 **완전 증명**(부분 → 종결). 하나라도 미달이면 **미달 축의 이름을 적고** 부분 증명으로 남긴다. 🔴 「대체로 떴다」로 종결하지 않는다.

## 6. 되돌림

- O-58: `.pre-o58` 원본 복원 → 게이트웨이 재기동 → `:8787` 응답 확인.
- O-57: 설정 원복 1줄.
- 컨테이너가 안 오면: `docker start` 3본 수동 → 그 사실을 **FAIL 로 적는다**(손으로 살린 것은 자동 복구의 성공이 아니다).

- 보고 = 前/後 두 칸 표 + 판정선 대조 + **못 잰 축의 이름**.

## A안 — Control Room (관제실)

### ① 무드·컨셉

산업 현장의 관제 벽면을 그대로 옮긴 화면이다. 방문자가 처음 보는 것은 «설명»이 아니라 **가동 중인 공장의 상태 그 자체** — 12대의 설비 카드가 한눈에 깔리고, 이상이 있는 한 대만 붉게 도드라진다. SCADA·Grafana 계열의 시각 언어를 따르되 촘촘함이 난잡함이 되지 않도록 계층을 3단(레일 → 트리 → 카드)으로 나눴다. 이 화면의 주인공은 **설비 상태**이며, AI는 그 위에서 호출되는 도구다.

### ② 레이아웃 구조

```
56px 아이콘 레일 │ 260px 계층 트리 │ flex 설비 카드 그리드(4열) │ 360px 알람·시나리오 도크
상단: 48px 앱바(내비 + 모드/세션/리셋) + 40px KPI 스트립(상시 고정)
```
- 내비 = **좌측 아이콘 레일 + 상단 텍스트 탭** 이중 구조 → 화면이 늘어나도 내비가 자리를 먹지 않는다.
- 모든 화면이 «좌 컨텍스트 / 중앙 작업 / 우 액션»의 3열을 유지 → 화면 간 이동에도 눈의 위치가 변하지 않는다.

### ③ 팔레트

**다크 기본**. 배경 `#0b0f14` → 패널 `#111823` → 경계 `#1e2a38`의 3단 뉴트럴. 텍스트 `#dbe4ef`/`#7d8fa5`. 상태 green `#31c48d` · amber `#f0a742` · red `#f0555c`, **AI·evidence = cyan `#38bdf8`**(상태색과 계열이 겹치지 않음). ID·수치는 전부 모노스페이스.

### ④ 대표 화면

`docs/product/mocks/direction-a-control-room.html` — Factory Overview 실물. 12대 카드 그리드, 24h 스파크라인, 우측 알람 도크의 「▸ 조사 시작」.

### ⑤ 장·단점

| | |
|---|---|
| 👍 | baseline §11.3 «dense but legible · neutral dark»에 **정면으로 부합** · §11.2 Incident 4분할 배치와 구조가 같아 화면 간 일관성이 공짜로 나온다 · 「진짜 운영 도구」 인상이 가장 강함 |
| 👎 | 첫인상이 복잡해 포트폴리오 방문자가 «어디를 봐야 하나»를 잠깐 헤맬 수 있음 · 여백이 적어 타이포·아이콘 완성도가 낮으면 곧바로 조악해 보임 |
| P0 5화면 수용 | ✅ 3열 셸이 5화면 전부를 그대로 담는다 — Incident(타임라인/센서/후보), Evidence(그래프/문서), WO(편집/근거), Compare(3열 결과)가 모두 같은 골격의 변주다. |

## B안 — Investigation Desk (조사 데스크)

### ① 무드·컨셉

화면이 먼저 **문장으로 말한다**: 「지금 조립 2라인의 CNC 밀링 한 대에서 스핀들 진동이 임계를 넘고 있습니다.」 그 아래 문제의 설비 하나만 크게 펼치고, 정상 설비는 조용한 목록으로 접는다. 따뜻한 차콜 배경에 여백을 넉넉히 주고 본문 타이포를 키워, 대시보드가 아니라 **조사 기록을 읽는 책상**처럼 느껴지게 했다. 이 화면의 주인공은 **AI의 근거와 서사**다 — 우측 도크에 이 설비에 붙어 있는 문서·안전 규정·정비 이력·고장 모드가 상시 노출된다.

### ② 레이아웃 구조

```
상단 텍스트 내비(밑줄 탭) · 좌우 40px 여백
본문 1fr (헤드라인 → 히어로 카드 → 조용한 리스트) │ 380px 근거 도크(고정)
```
- 2열. 카드 그리드를 쓰지 않고 **히어로 1 + 리스트 N** 패턴으로 시선을 강제한다.
- Incident 화면에서는 본문 열이 그대로 **조사 타임라인**이 되고 도크가 근거로 채워진다.

### ③ 팔레트

**웜 다크**. 배경 `#14120f` → 표면 `#1c1a16` → 경계 `#2f2b24`. 텍스트 `#ece7dd`/`#a49c8d`. 강조 amber `#d9a441`(주 액션), evidence blue `#7fb3d5`. 헤드라인만 **세리프**를 써서 «읽는 화면»의 성격을 만든다.

### ④ 대표 화면

`docs/product/mocks/direction-b-investigation-desk.html` — 헤드라인 문장 + EQ-CNC-204 히어로(3주 추세 차트 + 「3주 완만 상승 → 24h 급등 → 18개월 전 같은 부위 베어링 교체 이력」 서사) + 우측 근거 도크.

### ⑤ 장·단점

| | |
|---|---|
| 👍 | 이 PoC의 차별점(**근거를 인용하는 AI**)이 첫 화면에서 바로 읽힌다 · 3분 데모 서사(product-brief §5)와 화면 구조가 1:1 · 정보가 적어 시각 완성도를 내기 쉽다 |
| 👎 | «공장 운영 콘솔» 인상이 약하다 — 설비 12대의 동시 상태 파악이 A안보다 느리다 · 🔴 Incident 화면은 baseline §11.2가 **4분할**을 요구하는데 B안의 2열 서사 구조와 충돌해 그 화면만 예외 레이아웃이 된다 |
| P0 5화면 수용 | ⚠️ Overview·Evidence·WO·Compare는 자연스럽지만 **Incident 조사 화면은 4분할로 예외 처리**해야 한다(구조 일관성 1회 희생). |

## C안 — Blueprint (설계도)

### ① 무드·컨셉

공장을 **도면으로 그린다**. 격자 종이 위에 라인 3개를 프레임으로 두고 설비를 배치한 뒤, 센서를 지시선(leader line)으로 끌어낸다. 밝은 종이색 배경에 얇은 잉크 선과 모노스페이스 라벨을 써서 CAD 도면·기술 사양서의 시각 언어를 취했다. 이 화면의 주인공은 **구조와 관계**다 — 설비가 어디에 놓여 있고 무엇과 연결되어 있는지가 먼저 보인다. 지식그래프·온톨로지를 다루는 제품의 성격이 시각 자체로 드러난다.

### ② 레이아웃 구조

```
250px 계층 트리(+범례) │ flex 도면 캔버스(격자 배경 위 sheet) │ 340px 알람·SSOT 상태
상단 50px 앱바 · 캔버스 내부는 «도면 표제란(title block)» + SVG 배치도 + 색인 표
```
- 중앙이 **캔버스**라 Knowledge Explorer(그래프 탐색)로의 확장이 가장 자연스럽다.
- 표(색인)와 도면을 한 sheet에 얹는 «기술 문서» 문법.

### ③ 팔레트

🔴 **라이트 기본**. 종이 `#f5f3ed` · sheet `#fffefb` · 격자 `#e6e1d4` · 괘선 `#d3cdbe`, 잉크 `#22282e`. 상태 green `#2f7a52` · amber `#b0761a` · red `#b3352f`(모두 저채도 잉크 톤), 링크·AI = ink blue `#2f5d8f`.

### ④ 대표 화면

`docs/product/mocks/direction-c-blueprint.html` — 라인 3개 배치도 + SN-204-VIB 지시선 + 설비 색인 표 + 우측 SSOT 상태(문서 45·revision 60·index fresh·ontology v0.1).

### ⑤ 장·단점

| | |
|---|---|
| 👍 | **온톨로지·그래프 역량이 시각으로 즉시 전달**된다 · 문서 캡처·README·발표 자료에 그대로 실어도 읽힌다(다크 캡처보다 인쇄·슬라이드 친화) · 3안 중 가장 «남들과 다른» 화면 |
| 👎 | 🔴 **baseline §11.3의 «neutral dark background를 기본으로 한다»와 충돌** — 채택 시 baseline §11.3 개정이 선행되어야 한다(§0.3 절차) · 라이트 배경에서 센서 스트리밍·경보의 «긴박함» 표현이 약하다 · 저채도 잉크 팔레트는 대비 확보에 손이 더 든다 |
| P0 5화면 수용 | ✅ 담을 수 있다. 단 Incident 조사 화면의 실시간 진행 표현은 다크 대비 임팩트가 낮아 별도 강조 장치(진행 바·펄스)가 필요하다. |

## 구현 좌석 권고 — **A안**

근거 3가지(E3 소견):

1. **구조 일관성이 공짜로 나온다.** baseline §11.2가 Incident 화면에 «좌 timeline · 중앙 센서 · 우 후보 · 하단 evidence» 4분할을 못 박았는데, A안의 3열 셸은 그 배치와 같은 골격이다. B안을 고르면 5화면 중 가장 중요한 Incident 하나만 예외 레이아웃이 된다 — 7일 일정에서 예외는 비용이다.
2. **§11.3 정합이 완전하다.** C안은 좋은 화면이지만 채택하려면 baseline 개정(§0.3)이 먼저다. 지금은 Phase 0 동결 직전이라 baseline을 흔들 시점이 아니다.
3. **B안의 강점은 A안 안에서 회수할 수 있다.** 「헤드라인 한 문장」과 「근거 도크 상시 노출」은 A안 3열 구조의 우측 패널·상단에 그대로 얹힌다. 반대(B안에 A안의 밀도를 넣기)는 성립하지 않는다.

→ **A안 채택 + B안의 서사 요소 2개(상태 헤드라인 문장 · 근거 상시 도크) 흡수**를 권고한다. C안의 도면 캔버스는 **P1 `/knowledge` 화면의 시각 언어**로 남겨 두면 버리지 않고 살릴 수 있다.

🔴 최종 선택은 운영자 결정이다. 어느 안을 고르든 wireframe(T0-3)의 구조·라우트·인터랙션은 그대로 쓴다.

# 핵심 화면 5종 Wireframe v0.1

> 본 문서는 **구조·데이터·인터랙션**을 확정한다. 색·타이포·질감은 T0-2 3안 중 운영자 선택분을 따른다 — 아래 레이아웃은 3안 어디에 얹어도 성립하도록 그렸다.
> 기준 viewport **1440×900**(핵심 시연) · tablet 1024까지 대응(baseline §11.3).

## 0. 전역 셸 (AppShell — 5화면 공통)

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ ▣ FKT  Factory Knowledge Twin   Overview  Incidents  Compare   │ ◉ LIVE │ ⬡ a3f1 │ ⟲ │ ← 56px
└────────────────────────────────────────────────────────────────────────────────────────┘
   └ 로고/내비 ────────────────────────────────────┘  └모드배지┘ └세션┘ └리셋┘

[ ! ] Live AI 연결이 끊겨 Replay로 전환했습니다. 화면 흐름은 동일합니다.        [자세히]   ← fallback 배너(조건부)
```

| 요소 | 데이터 | API | 동작 |
|---|---|---|---|
| 모드 배지 | `◉ LIVE` / `◑ REPLAY` — 색 + **아이콘 + 텍스트 병행**(§11.3) | `GET /live/status` → `{online, checkedAt}` (30s polling) | 클릭 → 마지막 확인 시각 tooltip |
| 세션 칩 | `sessionId` 앞 4자 | `POST /sessions` (입장 시 1회) | hover → 「이 세션의 변경은 다른 방문자에게 보이지 않습니다」 |
| 리셋 | — | `POST /sessions/{sid}/reset` | 확인 모달 → 초기 상태 복귀 |
| fallback 배너 | `runFailed.fallback="replay"` 또는 `/live/status.online=false` | WS 이벤트 / polling | 자동 노출·수동 닫기 |

🔴 **P0 11항 중 4항(세션 격리·리셋·Live 감지·Replay fallback)을 전역 셸이 담당한다** — 5화면 어디서든 항상 보인다.

### 0.1 첫 진입 안내 · 용어 툴팁 (D-002 ④ «처음 봐도 이해 쉽게» — 운영자 최우선)

> 🔴 현 wireframe의 기본 독자는 «도메인을 아는 사람»이다(설비 ID·고장모드·SOP 코드가 설명 없이 노출된다). **처음 보는 방문자를 위한 장치 2개**를 화면 구조 변경 없이 얹는다.

**① 시나리오 시작 안내 카드** — 세션 최초 진입 1회, `/overview` 우측 도크 상단에 카드로 노출(오버레이가 아니라 **카드** — 화면을 가리지 않고 닫아도 다시 열 수 있다).

```
┌ 처음 오셨나요? ────────────────────────────── ✕ ─┐
│ 이 화면은 synthetic 공장 1곳의 실시간 상태입니다.  │
│                                                    │
│ ① 지금 설비 1대에 진동 알람이 떠 있습니다          │
│ ② 「조사 시작」을 누르면 AI가 근거를 모읍니다      │
│ ③ 원인 후보와 작업지시서 초안을 사람이 승인합니다  │
│                                                    │
│ 소요 3분 · 언제든 ⟲ 로 처음으로 돌아갑니다        │
│                        [ 안내 닫기 ] [ 조사 시작 ▸]│
└────────────────────────────────────────────────────┘
```
- 노출 조건: 세션의 첫 `/overview` 진입 1회(`localStorage` 아닌 **세션 상태** 기준 — 세션 격리와 일관).
- 재노출: 앱바 `?` 아이콘으로 언제든 다시 연다.

**② 도메인 용어 툴팁 원칙** — 다음 4종은 **처음 등장하는 지점마다** hover/tap 툴팁으로 «무엇인지 한 문장 + ID 읽는 법»을 준다. 별도 용어집 화면을 만들지 않는다.

| 용어 유형 | 예 | 툴팁 문안 원칙 |
|---|---|---|
| 설비 ID | `EQ-CNC-204` | 「CNC 밀링 설비. `EQ`=설비 · `CNC`=종류 · `204`=번호」 |
| 고장 모드 | `FM-BRG-WEAR` | 「알려진 고장 유형: 베어링 마모. 설비·부품에 미리 연결된 지식입니다」 |
| SOP·안전 규정 코드 | `SOP-BRG-INSP-014` · `SAF-LOTO-01` | 「승인된 작업 절차 문서 / 필수 안전 규정. 뒤의 `@r2`는 문서 버전입니다」 |
| 검색 전략 | Vector · Hybrid · GraphRAG | 「문서 의미 검색 / 구조화+문서 결합 / 관계 그래프 탐색」 |

- 원칙: **툴팁은 설명하되 화면을 가리지 않는다.** 라벨 자체를 풀어쓰지 않는 이유는 ID가 근거 추적의 단위이기 때문이다(T0-6 §3) — ID는 그대로 두고 의미를 덧붙인다.
- 상태 아이콘(●▲■)에도 동일 원칙 적용(§10의 «색만으로 구분하지 않는다»와 짝).

### 2.1 근거 상시 도크 (B요소 ② · D-002)

> 「AI 근거를 상시 노출한다」는 요구는 **새 패널을 만들지 않고** 이미 있는 두 영역이 겸한다 — 이것이 도크의 정의다.

| 도크 구성 | 위치 | 항상 보이는 것 |
|---|---|---|
| **후보 도크** | ② 우측 패널 **하단 고정 영역** | 현재 1순위 후보가 인용한 근거 요약 3건(문서·그래프·이력 각 1) — 후보 카드를 접어도 이 3건은 남는다 |
| **근거 스트립** | ② 하단 가로 스트립 | run이 지금까지 수집한 evidence 전량(kind 필터) — 조사 진행 중 **실시간으로 쌓인다** |

- 🔴 **비어 있지 않다**: run 시작 직후 evidence가 0건인 구간에도 도크는 「이 설비에 연결된 것」(SOP·안전 규정·정비 이력·고장 모드 — T0-6 R21~R23으로 **조사 전에 이미 알 수 있는** 항목)을 채워 둔다. 조사가 진행되며 「AI가 실제로 인용한 것」으로 대체된다.
- ③ Evidence 뷰는 이 도크의 **상세 뷰**이지 별도 화면이 아니다(딥링크만 독립).
- 목적 기준 대응: 근거가 상시 보이는 것이 「근거로 얻는 AI 신뢰」(목적 3)의 화면상 실체다.

### 2.2 TTAE 표시 규율 (F-9 · 🔴 측정-주장 경계 §0.2)

- ⓐ **조사 경과**는 실측값이므로 그대로 표시한다(`elapsedMs` 누적 → `totalElapsedMs` 확정).
- ⓑ **수작업 대비**는 실측 전까지 반드시 «**잠정 목표 · 미실측**» 꼬리표를 달고, 실측 후에는 `Target / Actual / PASS·FAIL`로 분리 표기한다. **단축률(%)을 실측 전에 화면에 쓰지 않는다.**
- 표시 문안 예: `조사 경과 1분 12초 │ 같은 조사를 사람이 수작업으로: 45분 «잠정 목표 · 미실측»` → 실측 후 `… 수작업 Baseline 42분(Actual) · 단축률 97%(Actual) · Target ≥50% ✅ PASS`.
- 목적 기준 대응: 이 1행이 「다운타임 단축」(목적 1)을 **눈앞에서 보여주는** 유일한 장치다.

| 공장·라인·설비 선택 | ① 트리·카드 |

## 10. 시각·접근성 규칙 (baseline §11.3 — T0-2 3안 공통 제약)

- neutral **dark** 기본 · 정상 green / 주의 amber / 위험 red · **AI evidence·graph path = cyan~blue**로 계열 분리.
- **상태를 색만으로 구분하지 않는다** — 아이콘(●▲■✓◷) + 텍스트 라벨 병행(위 wireframe 전부 적용).
- 애니메이션은 3곳만: 조사 단계 진행 · graph path 강조 · sensor streaming.
- chat-first UI 금지 — 입력창이 화면의 주인공이 되지 않는다(⑤의 질문 선택도 상단 1줄).
- 1440px 기준 3-column, 1024px에서 우측 패널이 하단으로 접힘, 모바일은 ①의 알람 확인과 ④의 승인만.

## 11. 목적 제1 기준 자기점검 (운영자 확정 · 4문제가 «장면»으로 보이는가)

| 목적 | 「눈앞에서 일어나는 장면」 | 화면 실체 | 상태 |
|---|---|---|---|
| 1 · 다운타임 단축 | 조사가 몇 초 만에 끝나는지가 숫자로 흐른다 | ② §2.2 **TTAE 표시행**(경과 + 수작업 대비) | ✅ 본 개정에서 추가(F-9) |
| 2 · 지식 사일로 해소 | 흩어진 3개 층(DB·문서·그래프)이 한 조사 안에서 합쳐진다 | ② 타임라인 3단계(structured→vector→graph) · ⑤ 3전략 비교 | ✅ 기존 |
| 3 · 근거로 얻는 AI 신뢰 | 모든 주장에 원문·경로가 즉시 따라붙는다 | ② §2.1 **근거 상시 도크** · ③ 인용 강조 · revision/hash·STALE 배지 | ✅ 본 개정에서 강화(F-11) |
| 4 · 안전 규정 구조 결합 | 안전 조치가 «지울 수 없는 항목»으로 작업지시서에 박힌다 | ④ 삭제 불가 안전 조치(`SOP -REQUIRES-> SafetyRule`이 UI 제약으로 나타남) | ✅ 기존 |

🔴 4번이 가장 강한 장면이다 — 관계 그래프가 **UI 제약으로 관철되는** 유일한 지점이라, 「온톨로지가 실제로 무엇을 하는가」를 말이 아니라 동작으로 보여준다.

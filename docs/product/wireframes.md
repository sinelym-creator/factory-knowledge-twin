# 핵심 화면 5종 Wireframe v0.1

> 본 문서는 **구조·데이터·인터랙션**을 확정한다. 색·타이포·질감은 T0-2 3안 중 운영자 선택분을 따른다 — 아래 레이아웃은 3안 어디에 얹어도 성립하도록 그렸다.
> 기준 viewport **1440×900**(핵심 시연) · tablet 1024까지 대응(baseline §11.3).

## 0. 전역 셸 (AppShell — 5화면 공통)

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ ▣ FKT  Factory Knowledge Twin   Overview  Incidents  Compare   │ ◉ LIVE │ ⬡ a3f1 │ ⟲ │ ← 56px
└────────────────────────────────────────────────────────────────────────────────────────┘
   └ 로고/내비 ────────────────────────────────────┘  └모드배지┘ └세션┘ └리셋┘

[ ! ] Live AI 연결이 끊겨 Replay로 전환했습니다. 화면 흐름은 동일합니다.        [자세히]   ← fallback 배너(조건부)
```

| 요소 | 데이터 | API | 동작 |
|---|---|---|---|
| 모드 배지 | `◉ LIVE` / `◑ REPLAY` — 색 + **아이콘 + 텍스트 병행**(§11.3) | `GET /live/status` → `{online, checkedAt}` (30s polling) | 클릭 → 마지막 확인 시각 tooltip |
| 세션 칩 | `sessionId` 앞 4자 | `POST /sessions` (입장 시 1회) | hover → 「이 세션의 변경은 다른 방문자에게 보이지 않습니다」 |
| 리셋 | — | `POST /sessions/{sid}/reset` | 확인 모달 → 초기 상태 복귀 |
| fallback 배너 | `runFailed.fallback="replay"` 또는 `/live/status.online=false` | WS 이벤트 / polling | 자동 노출·수동 닫기 |

🔴 **P0 11항 중 4항(세션 격리·리셋·Live 감지·Replay fallback)을 전역 셸이 담당한다** — 5화면 어디서든 항상 보인다.

| 블록 | 항목 | 출처 |
|---|---|---|

**인터랙션**

🔴 **live/replay 무차별 렌더**: 두 모드가 동일 `agent-events` 스키마를 쓰므로 화면 컴포넌트는 `mode`를 표시 배지에만 쓰고 렌더 분기를 하지 않는다.

## 10. 시각·접근성 규칙 (baseline §11.3 — T0-2 3안 공통 제약)

- neutral **dark** 기본 · 정상 green / 주의 amber / 위험 red · **AI evidence·graph path = cyan~blue**로 계열 분리.
- **상태를 색만으로 구분하지 않는다** — 아이콘(●▲■✓◷) + 텍스트 라벨 병행(위 wireframe 전부 적용).
- 애니메이션은 3곳만: 조사 단계 진행 · graph path 강조 · sensor streaming.
- chat-first UI 금지 — 입력창이 화면의 주인공이 되지 않는다(⑤의 질문 선택도 상단 1줄).
- 1440px 기준 3-column, 1024px에서 우측 패널이 하단으로 접힘, 모바일은 ①의 알람 확인과 ④의 승인만.

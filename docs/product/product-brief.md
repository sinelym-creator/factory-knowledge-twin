# Product Brief — Factory Knowledge Twin: AI Operations Console

## 1. 한 줄

공장 설비에 이상 신호가 떴을 때, AI 에이전트가 설비 상태·센서 추세·정비 이력·SOP·안전 규정·지식그래프를 **근거를 인용하며** 조사하고, 원인 후보와 작업지시서 초안을 만들어 **사람의 승인**을 받는 운영 콘솔.

## 2. 사용자와 관심사 (baseline §4.1)

| 사용자 | 콘솔에서 얻는 것 |
|---|---|
| 설비 운영자 | 지금 무엇이 이상한가 · 즉시 확인할 점 · 안전 조치 |
| 정비 엔지니어 | 원인 후보와 그 근거 · 유사 장애 이력 · 부품·SOP |
| 생산 관리자 | 생산 영향도 · 우선순위 · 작업지시서 상태 |
| 품질·안전 담당자 | 규정 준수 여부 · 근거 문서 · 승인 이력 |
| AI·IT Architect | 검색 구조(3전략 비교) · Agent workflow · 데이터 권한 · 평가 결과 |
| 포트폴리오 방문자 | 실제 제품 수준의 통합 설계·구현 증거 |

## 3. 문제

설비 이상의 원인 판단에 필요한 근거가 **구조화 DB(센서·알람·정비 이력)· 문서(SOP·안전 규정·매뉴얼)· 관계(설비-고장모드-부품-규정)** 세 층에 흩어져 있다. 기존 도구는 한 층씩만 본다 — 검색은 문서만, 대시보드는 수치만, 그래프는 관계만. 사람이 세 층을 오가며 조립하는 동안 판단이 늦어지고, AI를 붙여도 «근거 없는 요약»이면 현장은 신뢰하지 않는다.

## 4. 가치 (이 PoC가 증명하는 것)

1. **혼합 검색이 조립을 대신한다** — Structured + Vector + GraphRAG를 한 질의에서 결합하고, 세 전략의 결과 차이를 화면에서 직접 비교시킨다.
2. **모든 판단에 근거가 붙는다** — 원인 후보마다 그래프 경로와 문서 인용(원문 문장 강조)을 첨부. 근거 없는 문장은 내보내지 않는다.
3. **AI는 제안, 확정은 사람** — 작업지시서는 초안까지만. 편집·승인·반려는 human-in-the-loop.
4. **항상 시연 가능** — Vercel Sandbox의 deterministic replay로 노트북이 꺼져 있어도 전체 시나리오가 돌고, Live AI가 켜지면 같은 화면이 실시간 조사로 전환된다.

## 5. 3분 데모 서사 (P0 기능만으로 성립)

| 분 | 장면 | 화면 · P0 기능 |
|---|---|---|
| 0:00 | 방문자 입장 — synthetic 공장 전경, 라인·설비 상태 | Factory Overview |
| 0:20 | 이상 신호 — 설비 1대에 알람. Golden Scenario 실행 | 시나리오 실행·센서 추세 chart |
| 0:50 | AI 조사 — 에이전트가 단계별로 진행(계획→검색→그래프 추적→종합). 진행이 실시간 스트리밍(Live) 또는 replay로 흐른다 | Incident 조사 · agent event streaming/replay |
| 1:40 | 근거 확인 — 원인 후보 2~3개, 각각 그래프 경로 시각화 + 문서 원문 인용 강조. 검색 전략(Vector/Hybrid/GraphRAG) 결과 비교 | Evidence 뷰 · 전략 비교 |
| 2:20 | 작업지시 — AI 초안을 사람이 편집 → 승인(또는 반려). 승인 이력이 남는다 | Work Order 편집·승인 |
| 2:50 | 마무리 — one-click reset, 다른 방문자와 세션 격리 안내 | reset · session 격리 |

## 6. 경계 (공개 서사에 항상 붙는 문장)

- 모든 데이터는 synthetic — 실제 회사·설비·고객 데이터 없음.
- 실제 설비 제어 없음 — 작업지시·승인은 sandbox 안에서만.
- 공개 서비스는 replay/로컬 모델로 동작 — Claude 구독을 공개 API로 노출하지 않음.
- 배포 시점 수치는 «잠정 목표» — 실측 후 Target/Actual/PASS·FAIL로 분리 표기.

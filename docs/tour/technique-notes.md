## 0. 3단계 절차 — 우리가 실제로 밟은 것

```
[1단계 관찰] 참고 사이트를 본다 → 이 파일에 «자연어로만» 적는다
      ↓  (코드·변수명·옵션명·CSS 값·hex·z-index 를 적지 않는다)
[2단계 명세] 이 노트를 우리 규격(docs/design/t6-5-guided-tour-spec.md) 어휘로 번역한다
      ↓  (이 시점부터 참고 사이트를 다시 열지 않는다)
[3단계 구현] 명세만 보고 짠다 → PR 에 명세 링크와 출처 고지를 남긴다
```

**써도 되는 것 / 안 되는 것**

| 써도 됨 | 쓰면 안 됨 |
|---|---|
| 「말풍선이 아래로 안 들어가면 위로 보낸다. 상하 다 안 되면 좌우를 시도한다」 | 그들의 배치 함수 본문·분기 순서 그대로 |
| 「스포트라이트 여백을 픽셀 값으로 노출한다」 | 그들의 옵션 이름 + 기본값 조합 |
| 「Esc 로 닫고, 닫으면 포커스를 원래 자리로 되돌린다」 | 그들의 키 핸들러 코드 |
| 「오버레이는 구멍을 뚫어 대상만 조작 가능하게 한다」(일반 기법) | 그들의 path 문자열·색상 hex·z-index |

🔴 **가장 큰 발견은 부정형이다** — 판독한 여섯 곳 **전부** 회피 기준이 **「뷰포트 경계」**였다. **「옆의 읽을 글자를 안 가린다」를 하는 곳은 한 곳도 없었다.** 우리 런타임 겹침 회피는 이 축에서 앞선다. ⚠ 다만 **그들이 «못 한» 게 아니라 «안 한» 것**이다 — 대개 배경을 어둡게 덮어 문제가 안 생긴다. **우리는 배경을 살려 두는 설계**(원칙 3 「막지 않는다」)라 이 문제가 생겼다.

## 2. 참고하지 않기로 한 것

| 대상 | 사유 |
|---|---|
| intro.js · Shepherd.js | **AGPL** — 허용 목록 밖 |
| GuideChimp | **EUPL-1.2/상용 이중** — permissive 아님. 코드는 물론 **구조를 깊이 참고하는 것도 피한다** |
| Guide.js(이름만 알려진 것) | **403 으로 열리지 않았다** — 정식으로 볼 수 없는 자료라 **참고 목록에서 제외**한다(가장 단순한 해결) |
| tour-kit 상용 패키지(체크리스트·설문·공지 등) | 코어 밖. **데모 화면·코드를 열지 않는다.** 우리 투어는 코어 범위(tour·hint)만 겹쳐 자연히 지켜진다 |
| usertour.io | 🔴 **usertourkit.com 과 «다른 회사»다.** 검색하면 먼저 나오므로 혼동하지 않는다 |

## 3. 소견 (E3 · 확인 아님)

- 포커스 트랩·오토 플립·스포트라이트 여백은 **WAI-ARIA 권고와 공개 구현에 널리 존재하는 관행**이라 선행 기술이 두텁다. **위험이 낮다는 개발자 의견이지 법적 확인이 아니다.**
- 사업화(유료 전환·투자 유치) 전 **변리사 FTO 약식 검토 1회** 권고. 준비물이 이 파일이다 — 이미 자연어로 정리돼 있어 그대로 넘긴다. **이 노트를 지금 만들어 두는 두 번째 이유가 그것이다.**
- MIT 코드의 공개 리포·npm 페이지를 읽는 것은 이용 약관 대상이 아니다. 약관이 문제 되는 것은 **로그인이 필요한 유료 데모·대시보드를 보고 화면을 옮기는 경우**뿐이고, 우리는 하지 않는다.

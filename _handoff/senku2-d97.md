# D-97 판독 — 조사 1건에 게이트웨이 `POST /synthesize` 200 이 2건인 이유

> 센쿠2 56대 · 2026-09-11 · **코드 읽기만**(구독 0 · 무대 무접촉 · 코드 변경 0).
> 판정은 오케 몫이다 — 여기 적는 것은 **기전 · 단위 · 처방 후보 · 판정선 «제안»**뿐이다.

## 1. 기전 — 재시도도 2단 합성도 아니다. **D-84 안전규정 재요청**이다

`live_synthesis.synthesize()`(`services/ai-api/app/investigation/live_synthesis.py:614`)는
`for attempt in (1, 2)` 루프 안에서 게이트웨이를 부른다. 2회차가 도는 조건은 **하나뿐**이다:

```
safety_rules = safety_rules_in_evidence(evidence_text)   # 발췌 «본문»의 SAF-* id 집합
...
missing = unnamed_safety_rules(safety_rules, rationale)  # 답 문장이 호명하지 않은 id
if not missing: break                                    # ← 1회로 끝나는 갈래
if attempt == 1: notice = _guard_notice(missing); continue   # ← 2회차 = 같은 발췌 + 통지
```

- **오류 재시도가 아니다** — 예외(`_Rejected`·타임아웃·기타)는 전부 **즉시 return** 이다(루프를
  다시 돌지 않는다). 그래서 「2건 200」은 **둘 다 성공한 호출**이다(리바이2 관측과 일치).
- **2단 합성이 아니다** — 두 회차는 **같은 `candidates`·같은 `evidence_text`** 를 보낸다.
  다른 것은 `notice` 한 줄뿐이다(`_request_body(anchor, candidates, evidence_text, notice)`).
- **인용수 7→8 이 갈리는 자리가 바로 이것이다**: 통지가 「빠뜨린 `SAF-*` 를 문장에 그대로
  적어라」라서, 2회차 답은 그 규정을 문장에 넣는다 → 인용/호명이 한 칸 는다.
- 호출 경로는 **하나**다. `synthesize()` 를 부르는 곳은 `workflow.py:373`(합성 노드) 1곳뿐이고
  (`grep` 전수), 초안 단계는 게이트웨이를 부르지 않는다. 즉 **1 run = 1~2 호출**이며 3 이상은 없다.

### 🔴 「2배」는 상수가 아니라 «조건부»다

2회차는 **발췌 본문에 `SAF-*` 가 있고 + 1회차 답이 그것을 호명하지 않았을 때만** 돈다.
코퍼스에 `SAF-*` 는 **11종 실재**(`data/` 전수 grep · `SAF-LOTO-01`·`SAF-PPE-01` 등)이므로
자극 자체는 흔하다. 다만 **어느 비율로 미호명이 나는지는 모델 거동**이라 코드로는 못 말한다.
리바이2 관측(2/2)은 **그 시나리오에서 2회 다 미호명이 났다**는 뜻이고, 코퍼스 전체 비율은
**안 잰 값**이다. 따라서 실소모는 **run 당 1~2 · 상한 3 run 이면 시간당 3~6 호출**이다.

## 2. 상한이 세는 단위 — **run 이다. 호출이 아니다**

`_admit_run_caps`(`routers/investigations.py:103`)는 **run 생성 라우트에서 1회**(`:357`) 불린다.
합성이 1회를 쓰든 2회를 쓰든 계수는 **1**이다. 재사용 회차(`_reusable_run`)는 그보다 앞에서
return 하므로 아예 세지 않는다.

계약도 그렇게 적혀 있다 — v0.2.4 ①은 「**Live 조사** 상한」이고 계수 대상은 run 이다
(`packages/contracts/rest-api-v0.1.md:278`). **즉 구현은 계약 문면과 어긋나지 않는다.**

🔴 **어긋나는 것은 «목적»과 «단위»다.** `settings.py:91~` 은 이 상한의 목적을
「**구독 전체의 소모**를 막는다」로 적었는데, 구독을 소모하는 것은 run 이 아니라 **호출**이다.
목적이 호출 축인데 계수기는 run 축이라, 「시간당 3」이라는 예산 문면이 **최대 6 호출**을 덮는다.
D-97 은 「구현이 계약을 어겼다」가 아니라 **「예산이 자기가 세는 것과 다른 것을 약속했다」**이다.

## 3. 🔴 지금은 **2호출이 났다는 사실이 아무 데도 안 남는다**

`safetyOmitted` 는 **2회차에도 미호명일 때만** `true` 로 실린다(D-84 · 계약 v0.1.19 `:234`).
**2회차가 성공한 run** 은 `safetyOmitted` 가 실리지 않아, 페이로드만 보면 1호출 run 과 구별이
안 된다. 남는 것은 ai-api 로그 한 줄(`규정 %d건 미호명, 재요청 1회`)뿐이다.
→ 어느 처방을 고르든 **「이 run 이 몇 호출을 썼는가」를 세는 칸이 먼저 있어야** 사후 검증이 선다.

## 4. 처방 후보

### A. 호출 1회로 접는다(재요청 제거)

- **얻는 것**: run↔호출 1:1 · 예산 문면이 그대로 참이 된다 · 코드가 가장 단순하다.
- **잃는 것**: D-84 가 통째로 사라진다. 규정 미호명은 「덜 말한 답」이라 화면은 조용히 나빠지고,
  계측 지표(T5-1 답변 축)가 근거를 잃는다. **계약 v0.1.19 `:234` 개정이 필요**하다
  (`safetyOmitted` 의 뜻이 「재요청했는데도 누락」에서 「누락」으로 바뀐다).
- 변형 A′: 재요청을 **끄는 손잡이**(`FKT_SAFETY_RETRY=0`)만 두고 기본은 켠 채로 둔다 —
  시연·예산 압박 때만 끈다. 계약은 「구현 선택」 한 줄 추가로 끝난다.

### B. 상한을 **호출 단위**로 재정의한다

- **얻는 것**: 예산이 실소모와 1:1 이 된다.
- **잃는 것/비용**: ⓐ 계수 자리가 run 입장(`_admit_run_caps`)에서 **합성 호출 자리**로 내려가야
  하는데, 그러면 「거절은 run 시작 «후»」가 되어 방문자는 진행 표시 뒤에서 거절을 만난다
  (지금 설계가 일부러 피한 자리) ⓑ 화면 문면 「조사 N회 남음」이 **호출 N회**가 되어 방문자가
  읽는 단위가 바뀐다 ⓒ 계약 v0.2.4 ① 전체(코드·문면·검증 축 4개)가 개정 대상이다.
- **비용의 첫 줄이 구현이 아니라 계약 개정**이다.

### C.(내 제안) **예약 2 · 미사용 1 반납** — 단위는 run 그대로

- run 입장에서 **최악값 2를 예약**(`commit` 2회분)하고, 합성이 1회로 끝나면 **1을 반납**한다.
- **얻는 것**: 방문자가 읽는 단위는 run 그대로 · 예산 상한은 호출 기준으로 **절대 초과하지 않는다**
  (시간당 3 run = 최대 6 이 아니라 **상한을 호출로 환산해 고정**할 수 있다).
- **잃는 것**: 계수기에 «반납» 연산이 생긴다(지금은 append 만 있는 슬라이딩 창이라 되돌리는
  자리가 없다 — CAP3-FIX 에서 「되돌릴 자리가 없다」가 정확히 D-1 의 뿌리였다). 반납을 넣으면
  그 자리가 다시 생기므로 **반납은 「자기가 방금 넣은 기록 1개」로 좁혀야** 한다.
- 계약 영향: ① 문면에 「1 조사 = 최대 2 합성 호출 · 상한은 호출로 환산한다」 한 줄.

### D. 문서만 고친다(코드 0)

- 예산 문면을 「조사 3 / 호출 최대 6」으로 적고 계수기는 그대로 둔다.
- **얻는 것**: 오늘 당장 참이 된다 · 회귀 0. **잃는 것**: 실소모 상한이 여전히 2배로 열려 있다.

## 5. 판정선 제안 (어느 처방을 고르든 공통)

1. **계측 칸 먼저** — `synthesis.calls: 1|2`(또는 `safetyRetried: true`)를 페이로드/로그에 싣고,
   드릴에서 **run 1건에 대해 호출 수가 표에 뜨는 것**을 본다. 🔴 이 칸이 없으면 이후 어떤 초록도
   「2호출이 안 났다」를 증명하지 못한다(§3).
2. **대조군 2** — ⓐ 발췌에 `SAF-*` 가 **없는** run = 호출 **1** ⓑ 있고 미호명이 나는 run = 호출 **2**.
   두 갈래가 실제로 갈리는 것을 본 뒤에야 비율을 말한다.
3. **상한 실측** — 상한을 1로 낮춘 무대에서 `hourlyCap.used` 증가분이 **처방이 정한 단위**와
   같은지(run 축이면 1, 호출 축이면 2) 잰다.
4. **구독 계수 정본은 게이트웨이 `POST /synthesize` 200 건수**(리바이2 축) — ai-api 로그가 아니라.

## 6. 안 잰 것

- **미호명 발생률** — 모델 거동이라 코드로 못 말한다. 코퍼스에 `SAF-*` 11종이 있다는 것까지가
  정적으로 말할 수 있는 전부다.
- **2회차의 토큰 비용** — 같은 발췌를 다시 보내므로 1회차와 비슷할 것이나 **안 쟀다**.
- 위 모든 문장은 **읽기**에서 나왔다. 이번 판독에서 게이트웨이를 부른 적 0(구독 0).

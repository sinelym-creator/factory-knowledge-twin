  ⇒ 판정선 ②(대상 조작으로 갈림) = **대상**.
- 갈림의 실체는 **52px**: `_ts` 가 시간 축으로 잡았다 — `100ms 문서높이 3029→3081`,
  `대상절대top 511→563`. **88 − 36 = 52 = 그 성장분**이다.
- `direct` 는 그 성장 «전»에 한 번 제자리에 들었고(그 순간 top 36 · bottom 563 = 조건 만족),

- `operator` 는 걸음을 밟는 동안 성장이 이미 끝나 있어(`이동 0 · 변화 0`) 항상 성장 «후» 값을 잡는다.

### 2.1 진범 — 「도달했다」가 **래치**로 굳는다

`apps/web-console/components/tour/tour-overlay.tsx:210`

```ts
if (!settled && !userMoved) {
  …
  settled = okTop && okBottom;
  if (settled) return;
  …window.scrollBy({ top: want, behavior: "smooth" });
}
```

바로 위 주석(`:231~236`)은 **정반대**를 약속한다 — 「도달했다≠계속 도달해 있다 … 그래서 **래치를
걸지 않고** 창이 닫힐 때까지 다시 본다」. 그런데 **바깥 가드의 `!settled`** 가 그 재평가를 막는다.
한 번 참이 되면 `settled` 는 다시 계산되지 않으므로 사실상 래치다.

**비파괴 판별(대조군 · 2/2 일치)** — 정착(top 88) 뒤 **프로그램 스크롤 1px**(= `scroll` 이벤트 →
`onFrame` → `measure` 재호출 · `userMoved` 는 `wheel`·`touchstart`·`keydown` 만 세우므로 «사람»으로
오인되지 않는다 · 폴링 창 8초 안):

| rep | 정착 | 1px 자극 뒤 | 읽음 |
|---|---|---|---|
| 1 | top 88 · bottom 615 | top **87** · bottom 614 | 보정 0 ⇒ **래치** |
| 2 | top 88 · bottom 615 | top **87** · bottom 614 | 보정 0 ⇒ **래치** |

계기(measure)는 분명히 다시 돌았는데 보정이 없다 ⇒ 「계기 부족」이 아니라 **가드가 막은 것**이다.
